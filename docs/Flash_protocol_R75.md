# R75：协议解析与命令识别的 Flash 优化

2026-10-25，固件 **UI-R75-OPT**。本轮只完成用户选定的两项优化：协议数值解析的常量倒数、共用配置命令识别。不改 HAL、ST 库、控制参数或中断分发。

## 构建净收益

| 项目 | R74 | R75 |
| --- | ---: | ---: |
| Debug／Release Flash | 129000 B | 128272 B |
| Flash 余量（总容量 131072 B） | 2072 B | 2800 B |
| RAM（总容量 32768 B） | 23080 B | 23080 B |

本轮净回收 **728 B**。单独替换倒数后构建为 128520 B，回收 480 B；最终命令识别及同容量队列再回收 248 B。两项收益均按完整链接结果统计。相比 R73 的 131064 B，两轮用户代码优化累计回收 2792 B。

编译选项、Debug 的 `-g3`、Flash／RAM 真实容量均保留；原 RWX LOAD 段链接警告保留。无需重新配置 CubeMX。

## 1. 数值解析使用等价常量

原 `parse_number()` 对负指数执行 `1.0 / factor`，其中 factor 仅可能为 2.0 或 10.0。改为直接选择二进制双精度常量 0.5 或 0.1；它们与原除法结果相同。

继续使用 double 累积和指数缩放，保留原小数、科学计数法、十六进制浮点数、符号、前导空白、负零、次正规数及溢出／语法拒绝规则。最终控制接口仍接收 float，未将整个解析器降为单精度。最终链接已移除 `__aeabi_ddiv`／`__divdf3`，其他必要的双精度支持保留。

## 2. 配置命令只识别一次

将 Work、Motor1、Motor2、Feedback、Gear、Align、Focus 七类前缀集中到一张静态表。输入阶段识别后，将命令类型和完整参数写入队列；主循环按类型执行，无需再次比较前缀。

内部队列记录为 `uint8_t kind + char value[63]`，每条仍是 64 B，由编译期断言检查。四条队列和主循环的请求快照维持原容量。因已匹配的前缀至少占一个字节，移除前缀后，原来最多 63 字节的命令行参数完整放得下。

保留原先的外部命令拼写、大小写、最大行长、FIFO、满队列拒绝、每轮最多处理四条、USB／USART 分片上下文、Stop 特例、错误码、临界区边界和配置保存策略。无效参数仍先排队，再在主循环拒绝；Focus／Align 不新增保存请求，其他成功配置继续合并请求保存。没有改变公开协议 API 或 W25Q64 保存格式。

## 验证

`tests/motor_host/run.py` 全部通过，包含原 FOC／HSO／六步／双机／保护／编码器／Flash／协议回归。`tests/ui_host/run.py` 的应用格式化、菜单、按键、保存及 LCD 回归通过。

新增配置分发黑盒测试，覆盖：

- 七类前缀、全部工作模式、两路型号、三种反馈、两路 Focus／Align、十进制／科学计数／十六进制 Gear 参数。
- 四条 FIFO、第五条拒绝、从非零槽位跨界回绕、配置等待时阻止运动命令但允许 Stop。
- 非法参数、相近但不匹配的前缀、直接调用的 63／64 字节边界、超长串口行后的恢复、USB／USART 交错分片。

使用修改前保存的 **实际 R74 协议源码**和当前源码分别运行同一测试程序。配置／非法输入回归输出一致；将十进制及十六进制浮点解析结果写为原始 binary32 数据，**39816 个结果逐位一致**，包括负零和次正规数。摘要均为 `c5e024e9`，并额外对原始数据逐字节比较，而非仅比较摘要。

链接后强初始化／中断／控制和保护路径检查、ELF 导出 BIN 与交付 BIN 一致性检查通过。`Drivers`、`Middlewares`、`ThirdParty`、KK_UI 核心以及原中断入口的 153 个文件与基线 SHA256 一致。UI 应用文件本轮仅更新固件版本。尚未烧录实板。
