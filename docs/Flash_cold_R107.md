# R107：诊断显示和命令解析体积优化

固件 `UI-R107-SIZ`，以包含编码器方向修复的 R106 为基线。保留全部显示行、菜单、命令、Native／JustFloat、USB／USART 及保护行为，无需修改 CubeMX。

## 实际资源

| Debug / Release | R106 | R107 | 变化 |
|---|---:|---:|---:|
| Flash | 131056 B | 130808 B | −248 B |
| Flash 剩余 | 16 B | 264 B | +248 B |
| RAM 总分配 | 29992 B | 29984 B | −8 B |

本轮未达到此前争取 1 KiB 维护余量的目标。264 B 仍只适合少量修复，不能作为后续功能扩展的充分预算。函数符号会受到 LTO 内联及共享影响，不把单个函数的缩小量当成整机净收益。

## 保留的修改

1. 诊断显示继续共用原 `refresh_values()`。3 字节描述项改用 10 位的四字节单位目标偏移、6 位格式和 8 位快照偏移，增加十六进制及连续两个 uint16_t 的格式。编码器 Age、VREF 原始值／校准值及 ADC 错误使用相同入口。目标缓冲偏移、格式数量和成对字段布局均有编译期检查，读取使用 memcpy。
2. 参考电压保留原来的 mV 四舍五入计算，再用已有定点输出器打印三位小数。删除这条路径不再使用的格式字符串；字号、字形、图标和显示文字不变。
3. Work、Motor、Feedback、Format 及 HSO 子命令共用严格的完整文字匹配器。Custom 的可用性、M2 禁止 ESC、配置和运行准入继续由原接口检查，未增加回调表或动态分配。
4. 前缀匹配时一次取得参数起点；共享两处 M1/M2 前缀检查，并合并四类标量运动命令的分类。Stop 的立即执行和取消队列、来源仲裁、过期请求拒绝、数值解析和临界区保留。
5. 固件版本和 HTML 兼容上限同步为 107，协议 schema、命令拼写、线格式、存储版本及布局均不变。

## 撤回的试验

- 独立增加整数诊断遍历器：净增大 72 B，撤回，改为复用既有遍历器。
- 4 字节的扩展显示描述项：只取得很小收益，改为保留 3 字节编码。
- 强制拆出更多配置／HSO 处理函数：增加 32～72 B，未保留。原有函数级优化和官方／核心编译参数保持基线。

## 验证

- UI、存储、LCD、按键与设置回归通过。新 `--formatter-baseline` 选项用同一测试状态编译前后两份应用，858 条诊断行逐字相同，仅规范化 FW 版本文字；查询不修改本地页面、草稿或设置。
- 控制器、FOC、独立 HSO、命令队列、来源仲裁、立即 Stop、过期／取消请求、Native／JustFloat 及双传输回归通过。增加枚举拼写、截断／多余字符、空参数和截断轴前缀的拒绝检查。
- 修改前和修改后的协议同时通过扩展后的测试；159264 B 的数值目标轨迹完全一致。
- HTML 控制台和真实 Edge Web Serial 格式切换回归通过。
- 36 项 CubeMX 配置变更回归、两个实际 ELF 的启动／串口／中断路径和各 139 项 Thumb 异常路径检查通过。
- 尺寸报告核对 211 个受保护文件及官方／核心编译参数，与基线一致。所有正常构建继续执行 CubeMX 检查。
