# UI-R35-TRACK：4015 小角度高速往复跟随

本页保留 R35 的高速跟随记录。当前 UI-R38-SMOOTH 的移动输入整形、R37 停止保持、验证及局限见 [4015_moving_smoothness.md](4015_moving_smoothness.md)。

目标工况：4015 从轴、Curr Loop=On、Pos Speed=120、空载、±10°、每秒完整往复 4 次。按正弦机械角度计算，峰值速度 4.39 rad/s，峰值加速度约 110 rad/s²。R34 参考加速 55、后级给定加速 100 均会限制这个工况。

R35 已实现参考、测速与外环处理的优化。板上效果尚未验证；模型中的惯量、摩擦和电流执行器均未经过实物辨识。

## 使用

1. 烧录本次 Debug 或 Release 固件，确认 About → FW 为 **UI-R35-TRACK**。
2. 保持实际从轴型号为 4015、Curr Loop=On，Pos Speed=120，Speed Limit=120。可以选择 M1 或 M2 为从轴。
3. 手动摆齐两轴后按 OK 或发送 Follow，建立本次共同起点；从低频往复逐步增加到 4 Hz。
4. OK 停止、KEY2 停止返回；故障后仍需显式重新 Follow，编码器/ADC/过流/过载故障按原流程处理。

本版不需要重新生成 CubeMX，不更改设置的保存布局。2804、4015 电压模式、普通 Speed/Position、同步控制及单 M1 HSO 的控制预设保留。

## 处理方法

参数位于 `motor_params.c::MOTOR_4015.follow_current`。每次 Follow 绑定实际从轴和已确认的电流模式，运行中未确认的设置草稿不能切换参数。

| 项目 | R34 | R35 的 4015 电流跟随 |
| --- | --- | --- |
| 参考加速 | 55 rad/s² | 按跟随误差连续变化，55～180 rad/s² |
| 参考减速 | 100 rad/s² | 按跟随误差连续变化，100～500 rad/s² |
| 位置误差修正 P | 3 | 3 |
| 附加相对速度反馈 | 0.6 | 0；由独立速度 PI 反馈处理 |
| 速度 PI 比例项 | 0.05，另有上行相对速度反馈 | 按速度误差连续选择 0.05～0.10 A/(rad/s) |
| 速度 PI 积分项 | 0.5 | 0.5，饱和且误差继续推向饱和时暂停积分 |
| 后级速度给定加速/减速 | 100/150 rad/s² | 连续变化至最多 300/600 rad/s² |

这里的加减速数值是参考/指令约束，不保证真实轴达到同样加速度。正反方向仍先减至零，再进入相反方向；速度及 Iq 上限继续有效。

用从轴相对最终主机目标的真实位置误差计算权重：误差不超过 0.1 rad 时使用快速参考；0.1～0.2 rad 之间连续过渡；误差达到 0.2 rad 后恢复更缓的追赶参考参数。该权重同时作用于参考加减速、速度平滑、主机测速混合及后级速度给定斜坡，避免落后很远时继续积攒高速参考。快速端参考响应参数为 120 s⁻¹，缓慢端沿用 R34 的响应 24 s⁻¹。保留移动目标停止距离包络；参考位置由速度连续积分，不在新目标或限速变化时直接跳变。

两轴使用初始化于 Follow 起点的 alpha-beta 状态估计：每 1 ms 预测位置，以新机械位置的残差修正位置和速度，alpha=0.5、beta=0.08。快速从轴速度反馈直接使用此估计；主机速度按追赶权重与原测速混合。原有 4 ms 差分＋5 ms 低通测速继续服务于诊断、准备/停止判断及其他控制方式。Status/普通遥测显示的速度仍是原测速，并非新增观察器的内部速度。

速度比例项在误差接近零时保留 0.05，速度误差绝对值达到 1 rad/s 时升至 0.10，中间线性过渡，以兼顾小误差噪声与快速纠偏。该比例项仅在快速跟随外环求值时使用；普通模式的 PID 参数保留。Iq 饱和时的条件积分允许反向误差卸载积分，减少制动时继续积累输出；电流内环的既有处理和全部保护继续有效。

本版没有填入未经辨识的 J/Kt，也未加入惯量电流前馈。后续可使用测量数据辨识电流到加速度增益，再实现[调研方案](High_frequency_hand_follow.md)中的电流前馈。

## 相同模型下比较 R34 / R35

主机为 ±10°、4 Hz，调用真实两轴协调器和外环，运行 6 s，去掉前 1 s，用后续 20 个完整周期计算基波幅值比、相位及角度误差 RMS。模型包含 14 位角度量化、测速、静/动摩擦、齿槽扰动以及 250 rad/s 一阶电流执行器；电流到加速度增益选 300/1500/3000 rad/s²/A 检查不同响应。它没有验证真实 RL/PWM、电压饱和、回馈或通信时延；这些增益不能当作实机辨识结果。

| 模型增益 rad/s²/A | R34 幅值比 → R35 | R34 相位 → R35 | R34 角误差 RMS → R35 |
| --- | --- | --- | --- |
| 300 | 0.620 → 0.874 | −106.4° → −39.4° | 9.31° → 4.54° |
| 1500 | 0.632 → 0.890 | −69.8° → −8.1° | 6.96° → 1.25° |
| 3000 | 0.578 → 0.868 | −62.7° → −2.5° | 6.36° → 1.02° |

M1/M2 结果接近，表格保留四舍五入后的 M1 数值。相位栏是周期信号的相位角，不是轴的机械角度差。模型仍有幅值衰减，较慢执行器也仍有明显滞后，不能据此保证实机完全重合。

沿用的 1 rad 到位模型，R34 到达 90% 为 0.335～0.385 s，R35 为 0.310～0.326 s；R35 最大到位峰值约 1.0084 rad。+1→−1 rad 反向模型最大峰值从约 1.127 降至 1.114（以反向目标绝对值为基准），仍有残余超调。匀速、变速、限速变化、偏置、负齿轮比、Stop/Follow 重启及两轴互换继续通过原有界限；新增 4 Hz 往复后停止、积分饱和/反向恢复检查。

所有模型中的 Iq 指令仍在 ±1.2 A 内。4 Hz 动作时指令变化率增加是可能的，最高模型约 10 A/s RMS，不宜仅用“角度更快”评价实际平顺程度。上板需要同时记录主从角度、误差、Iq 给定/反馈及母线电压。

## 验证与构建

- `python tests/motor_host/run.py`：两轴控制、上述模型、采样/保护、编码器与共享 SPI2、HSO/协议回归通过。
- `python tests/ui_host/run.py`：界面、按键、存储和 LCD 驱动回归通过。
- `python tests/usb_host/run.py`：CDC 并发与恢复回归通过。
- `python tests/motor_host/check_startup.py`：两种固件启动调用顺序、强 MSP 实现、R35 版本及 ELF/BIN 一致性通过。

Debug：Flash **130772 / 131072 B**（余 300 B）、RAM **21576 B**。Release：Flash **129964 B**（余 1108 B）、RAM **21480 B**。SPI/GPIO HAL 与已有应用代码共同启用 LTO 回收重复代码；HAL 启动和 HSO 快环的编译设置保留。Debug/Release 的 ELF、BIN、MAP 已生成；原有 RWX LOAD 和 LTO 串行分区链接提示保留。尚未烧录或做硬件闭环验证。
