# R106：修正辨识参数应用后的编码器方向

固件 `UI-R106-DIR`。修复参数辨识后 Apply M1 或选择 Custom 时反馈方向反转、给定速度后堵转且 Iq 达到限幅的问题。无需修改 CubeMX。

## 原因与修正

辨识使用 `MT6701_GetRawAngle()` 的原始 14 位计数。记录中极对数的正负号表示：施加正方向电角度旋转时，原始计数增加还是减小。这个约定及保存格式保持不变。

编码器驱动发布给 FOC 的 `Angle` 已经是 `2π − 原始角度`。R104/R105 在应用记录时却直接把原始计数方向用作 Angle 的方向，因此反馈的机械角度、速度和电角度都用反了。重新对齐只能校正零点，不能补偿方向错误。

R106 在 `MotorParams_SelectAxis()` 装载 M1 电参时，将记录方向转换为 Angle 的方向：

| 辨识记录 | 运行时 encoder_direction |
|---|---|
| PP 11− / 原始计数负方向 | +1 |
| PP 11+ / 原始计数正方向 | −1 |

2804 同理。修正同时覆盖 Apply M1、Custom 1/2/3 及上电加载的旧记录。M2 继续保留自身基础预设的编码器安装方向，不复制 M1 的方向。Rs、Ls、磁链、电流 PI 和所有保护的计算及限值均未修改。

## 使用

已有 R104/R105 的辨识、应用及 Custom 数据可继续使用，不需要重测、清空或重新保存。烧录后重新启动并完成正常对齐；先在空载下用 5～10 rad/s 验证实际速度符号与目标一致、电流不再持续顶住限幅，再恢复原目标速度。软件已验证，实板效果仍需烧录确认。

若暂时使用旧固件，可停机后选择对应的 4015/2804，执行 `Preset M1` 并重新对齐，恢复程序预设电参和方向；最后一次辨识结果仍保留。仅切换型号再切回不会清除该型号已应用的记录。

## 验证与资源

- 新增真实链路回归：MT6701 SSI 帧 CRC／DMA 解码 → 已应用／Custom 电参 → 实际编码器角度源。覆盖 2804/4015、两种原始计数方向、正反向约 38 rad/s、多圈及跨零点；机械角度、速度和对齐后的电角度均与独立物理轨迹比较。相同测试使用修改前源码会失败。
- 实际控制器回归覆盖 Apply／Preset、Custom 选择、旧记录启动加载、PI 更新、对齐失效及运行时拒绝修改；原有编码器故障／恢复、Flash 共享和保存、HSO、协议／JustFloat、设置／UI／HTML 回归通过。
- CubeMX 配置变更回归，以及 Debug/Release 实际链接镜像的启动和异常路径检查通过。ST 官方库、生成配置、核心 UI 与编译选项未修改。
