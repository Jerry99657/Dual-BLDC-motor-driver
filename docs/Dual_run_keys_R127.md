# R127：双机 Run 短按漏检

固件：`UI-R127-KEY`，Native 配置回执编号 127。基线为 R126。

## 现场数据与判断边界

双机独立、同速等模式中，OK／KEY2 常需多次短按，长按更容易触发；KEY1 正常。单机和手动 Follow 未出现相同问题。同步速度模式读到 ADC IRQ Max 81.8 us、Outer Max 796.7 us、Outer E/G/S 0/0/0。

DispErr 为 21，但后续停留 Diagnostics 或再次进入 Run 都未继续增加，因此不能把这次漏按直接归因于正在重复的显示恢复。ADC／外环数值是峰值，外环计时包含高优先级抢占，也不能将两者直接相加作为 CPU 占用率。

旧代码只在主循环调用 `ui_input_poll()` 时读取 GPIO，没有保留发生在两次读取之间的短按。双机控制增加高优先级工作，绘图和其他前台服务也会拉长读取间隔。这里的问题是**采样间隔可能变长**；GPIO 读取本身没有一个不断缩短的检测窗口。KEY1 的 EXTI 独立于该路径。

已用真实 UI／按键／应用代码复现：主循环每 80 ms 执行一次时，完全落在两次读取之间的 35 ms 按压被旧轮询方式漏掉。80 ms 是测试条件，尚未在用户板上测出实际轮询间隔；最终效果仍需上板验证。

## 修改

1. 在现有 TIM2 的 1 kHz 更新分发中采样六个物理键，并对 OK／Back 分别消抖。此处只读 GPIO、消抖、记录 OK／Back 的按下状态，不调用 UI、SPI、存储或电机停止业务。
2. 对独立、同步速度、同步位置模式中正在输出的 Run 页面，暂存已消抖的 OK／Back 短按。主循环继续向 KK_UI 提交输入，由原有页面逻辑执行确认／停止／返回。
3. 按页、轴、工作模式、Run 控制模式和当前轴输出请求状态维护上下文。一轴停止而另一轴继续运行时，也取消停机轴的旧输入。上下文变化、故障停机、全局停止或显示错误恢复会取消旧输入；超过 1 s 的未处理输入丢弃。连续未处理的同键短按合并，避免恢复后重放一串启动／停止。
4. 页面执行事件后确认消费。保持物理按住期间不重复触发；若下一次短按先于前台观察到松开，则先向 KK_UI 提供完整的松开消抖阶段，再交付下一次按下，覆盖“确认新数值后再按停止”。
5. 主循环将最终按键读取放到 UI 上下文／故障维护之后，避免先读出的旧暂存键在故障取消后仍被交给页面。

单机、Follow 的输入交互保持原有处理；KEY1 仍为全局中断停止。所有电机动作都继续由主循环原有业务执行，正常停止语义和“目标改变时 OK 确认，未改变时 OK 停止”保持不变。

另修复一个独立的 LCD 传输等待点：DMA TC 到来时 FIFO／移位器可能仍忙，旧 SPI3 路径需要主循环再次调用 Service 才能交付完成并启动下一块。现在利用已有 SPI3 全局中断收尾，最多尝试四次后关闭该中断并保留主循环／显示超时兜底，不在 IRQ 等待 BSY。正常主机测试中，前台不服务时从旧路径的 0 块回调改为可完成全部 20 块。该问题确实存在，但稳定不增长的 DispErr 不能证明它是本次所有漏按的直接原因。

## CubeMX 与边界

无需重新配置 CubeMX；使用已有 TIM2 1 kHz 和 SPI3 IRQ。引脚、时钟、NVIC 优先级、SPI 格式、DMA 句柄与映射仍取生成配置。配置检查新增 SPI3 全局 IRQ／正确句柄路由的缺失拒绝测试，兼容工程原有 SPI USER CODE 委托方式。

不修改 ST HAL／LL／CMSIS／USB／HSO 库或 KK_UI、KK_OLED 核心。生成文件仅移动 `Core/Src/main.c` 的 USER CODE 3 内按键读取位置；检查工具只对这段明确的移动放行，其余受保护文件和编译选项仍严格核对。控制频率、电流阈值、外环超期阈值均未放宽。

## 验证与资源

- 独立／同步速度／同步位置的 35 ms OK、KEY2 短按：80 ms 前台间隔下，禁用周期捕获时漏检，启用后各执行一次停止。涵盖未处理松开时第二次 OK、持续长按、故障取消、轴切换取消、一轴停止但另一轴继续运行、停机时仍按住 OK 后松开再重新启动。
- UI 仍保留显示恢复时不重放当前确认键的行为；历史显示错误不会被本次修复自动清零。
- Cortex-M4 实际链接代码模型覆盖消抖不足／满 20 ms、物理松开后保留、上下文关闭、已消费按住、双键、过期和毫秒回绕。初始非运行外环路径由 212 条模型指令变为 326～362 条；模型有外设／查询边界替代，**不是板上周期或微秒测量**。
- SPI 原有三端口、600 组 DMA 重映射、错误／中止／回调竞争和寄存器写入次数回归通过；新增 FIFO 尾部自动衔接、四次上限及故障退回验证。
- UI 68 组图像／帧流、64857 次文字绘制、870 行诊断与基线一致（仅固件标识归一化）。原有控制、保护、编码器、HSO、辨识、协议、JustFloat、上位机回归通过。
- Debug／Release 构建、CubeMX 变更测试、实际 IRQ／采样集成、外环保护与异常向量检查通过。
