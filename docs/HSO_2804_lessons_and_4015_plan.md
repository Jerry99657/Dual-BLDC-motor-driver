# 2804 HSO 调试复盘与 4015 调试准备

记录日期：2026-10-19。代码基线：UI-R19-45RPM。
本记录仅整理经验和下次准备，不修改当前固件。

## 1. 本次可以确认什么

已集成 MCSDK 6.4.2 的官方 HSO / ImpedCorr 静态库；外围采样、磁链学习、接管、保护和 UI 为本工程实现。
用户实板上曾成功进入 CONTROL，但出现过资格不稳定与改速角度失锁，尚未证明全运行范围稳定。
最新 R19 的减速策略通过编译与主机回归，尚未收到其完整实板验证结果。
主机的 HSO 边界使用替身，不执行 ARM 库，不能用主机通过来证明实际角度精度。

2804 相电阻较高，会增加电阻压降与电流误差补偿的重要性，但本次没有完成排除全部采样、
参数与时序因素后的对照实验，不能把高 Rs 当成已证实的唯一根因。
4015 只是尺寸/型号信息；是否更合适，还要看实际绕组、极对数、Rs/Ls、磁链和采样质量。

用简化非凸极电机电压方程理解误差来源：

```text
e ≈ v - Rs*i - Ls*di/dt
```

因此电流测量误差 Δi 会带来约 Rs*Δi 的电阻补偿误差。
以本次 Rs=2.3Ω 为例，0.1A 的测量误差等效约 0.23V；这只是误差传播示例，不表示实测误差为0.1A。
低速时可用观测信号较弱，参数和采样误差更值得先排查。换低电阻电机还可能需要更大的采样量程，
不能假定尺寸更大或电阻更低就一定更容易。

## 2. 调试中遇到的问题和经验

| 现象/证据 | 结论与处理 | 下次沿用的经验 |
| --- | --- | --- |
| MCU 先上电、母线后接入，曾有 Bus 不更新或未就绪 | 保持连续采样；0V是测量值，驱动许可另判定。时间戳读取顺序也修复了跨中断减法下溢 | 不用“没有母线”停止测量；区分0V与NO DATA |
| IU 零点约2047，故障记录 RUN U 0，停机后恢复2045附近 | 原始值快照区分零点失败与运行异常；发现规则/注入异步碰撞风险，按勘误思路错开触发 | 先看原始码、零点、故障瞬间，再判断电流或硬件；不直接屏蔽0值 |
| Curr Loop 关闭，手动加载触发 M1 OVERLOAD | 电压控制不等于恒流；原预算对手动加载偏保守，额定值与试验过载预算分开 | 分清电压目标、电流目标、瞬时保护与持续过载 |
| H Error 约-5～15°，H Qual反复0～24ms | 单帧越过15°会使原先200ms连续资格计数归零 | 用可诊断、有限容错的资格累计，不无限放宽角度 |
| TRACKING 后 Use 立即 LOST | 原先入场和保持共用严格门限；后来分开，增加保持确认与过渡 | 入场、保持、严重故障各用独立规则；一次TRACKING不等于已经稳定可用 |
| Speed:0 后 LOST，新Speed不能起转 | 正常退出与异常锁存混在一起 | 正常停车、反转、低速退出要有明确状态；Learn不是低速运行模式 |
| 首次100→20停转，第二次才运行；H Lost=ANGLE、Feedback=ENCODER、Drive=READY | 角度失锁的停机处理清零了第一次目标；待处理故障与新命令时序也已处理 | 记录首因；保证新命令不会被旧故障随后覆盖 |

ADC 相关依据：ST [ES0431 Rev9 §2.5.10](https://www.st.com/resource/en/errata_sheet/es0431-stm32g431xx441xx-device-errata-stmicroelectronics.pdf)
说明 Rev Y 存在转换冲突导致首项错误为0的问题。本板 ChipRev 尚未在本次对话中确认，
不能写成已经证实所有0值都来自该勘误。目前 VBUS 每5次注入序列结束后触发一次，约2kHz，
TIM6不再自由运行，迟到回调跳过不安全窗口。

## 3. 目前保留下来的实现

- TIM1/TIM8 同频同步约10kHz；单一 ADC1 JEOS 作为快速控制入口。
- ADC1/ADC2 注入同步，IU/IV 同时采样。IW及三相电压位于后续rank，不能认为整组八个量同时取得。
- VBUS 独立于驱动状态连续更新，0V、零点校准、故障停机期间均保持测量。
- 编码器先完成有感运行，再旁路观测/学习磁链，最后手动 HSO:Use。
- 接管完成后电角度和速度反馈直接来自HSO；编码器仍用于独立校验和低速回退，不是可拔掉编码器的成品方案。
- 资格累计需要2000个严格合格帧；仅15～20°的小角度越界允许有限暂停，最多总计50帧、连续10帧。
  暂停帧不计进度；Use执行当帧仍需通过严格条件。保持与硬故障规则详见集成文档。
- R19：正常减速在实测45rpm以上保持HSO，低速/停车/反转先减到边界再平滑返回编码器。
  HSO减速参考50rad/s²，过渡约10ms。真正失锁仍停机；健康时新Speed可在编码器模式重新起转。
- 首次失锁原因保留在H Lost，下一次成功Use清除；正常退出不自动学习磁链。
- Debug保持真实128KiB Flash限制，应用/库分级优化；没有通过放大链接器Flash来掩盖溢出。

## 4. 换4015前必须重新确认的参数

| 项目 | 需要记录的内容 |
| --- | --- |
| 具体电机 | 完整型号、KV、厂商绕组说明；不能仅写4015 |
| 极对数p | 实测或可靠资料确认；机械角度、电频率和切换速度换算都依赖它 |
| 供电 | 额定电压、计划母线、供电限流与允许的回馈电压 |
| 电流 | 连续/短时峰值，以及相峰值、相RMS或母线电流的口径 |
| Rs | 温度、测量方法、引线影响、星/三角接法，最终使用控制等效相值 |
| Ls | 测试频率、绕组接法、线间/相值口径；不要未经确认直接套用铭牌线间电感 |
| 磁链 | 重新测量或学习，使用物理Wb；不能照搬2804或示例命令中的0.003 |
| 编码器 | 机械方向、相序、零点对齐；每次重新接线后核验 |
| 控制参数 | 电流/速度PI、加减速斜率、对齐电压、各项保护按新电机重新设置 |

若已确认是星形绕组，直流线间电阻与相电阻有约2倍关系，还需扣除引线/接触电阻；
接法不明时先确认。电感涉及测试口径和磁耦合，不用同一条电阻换算规则机械套用。

### 不能只改HSO:Motor命令

`HSO:Motor:Rs,Ls,Flux` 只修改观测器配置，不会同步更新控制器全部电机参数。
当前仍有2804直接引用，需要下一次统一适配，而不是只新增一个未启用的MOTOR_4015：

- `Core/Src/main.c`：编码器极对数、StHso_Init传入的电机。
- `mycode/JerryFOC.c`：active_motor及PI/滤波器的实际初始化值。
- `mycode/motor_sampling.c`：瞬时过流、持续过载仍直接读取MOTOR_2804。
- `mycode/motor_params.c/.h`：铭牌、电压限制、试验过载参数与控制参数。
- `mycode/ui_app.c`：About电机名称及相关显示；设置存储可能沿用上次Curr Loop/速度范围。

特别注意，当前对齐是电压方式，`Ud=min(3V, Rs*Irated)`；更换电机必须先使用新参数并限制对齐电流，
不能让低电阻电机沿用2804的1.15V对齐设定而不核验电流。

## 5. 硬件和时序：哪些保留、哪些复核

现有 INA240A2 + 10mΩ 的传输系数为 **0.5V/A**，REF1=AGND、REF2=REF3.3V，
零电流理论输出1.65V。3.3V ADC的理想轨到轨换算约±3.3A，但放大器输出摆幅、ADC范围与误差
都会缩小可用区间，不能将其当成可保证的双向满量程。
依据：[TI INA240数据手册](https://www.ti.com/lit/ds/symlink/ina240.pdf)。

如果4015需要的相电流超出现有准确量程，须先评估分流阻值、增益、功耗及ADC量程；
改硬件后同时更新CURRENT_AMPS、HSO归一化尺度和保护门限。不能只提高max_current。
目前0.5A额定/目标、2A瞬时停机、0.8A过载基准/3秒预算，都是2804配置，不能直接当4015参数。

端电压分压为(10k+10k)/2k，比例11；22nF与下臂并联，等效时间常数40µs，
极点25000rad/s（约3.98kHz）。这些首先是板级参数，换电机不自动改变。
当前对10kHz PWM纹波的抑制有限，4015仍需用示波器核对采样时刻和纹波。
若调整RC或PWM/ADC顺序，HSO的Filter Pole/Delay必须一起重新确认。
Delay=0.019表示约1.9µs采样错位/100µs周期，不能拿40µs模拟RC替代它。

## 6. 45rpm不能无条件照搬到4015

```text
电频率 fe = p * rpm / 60
机械速度 rad/s = rpm * 2*pi / 60
```

当前5Hz是本工程设置的观测资格下限，不是ST承诺的所有电机物理最低速度。

| 极对数p | 45rpm的电频率 | 仅达到软件5Hz所需机械速度 |
| --- | --- | --- |
| 4 | 3Hz | 75rpm |
| 7 | 5.25Hz | 约42.86rpm |
| 14 | 10.5Hz | 约21.43rpm |

因此下次先确认4015极对数，再选有实测余量的进入/退出边界；不能固定45rpm后再期待任何电机都通过。
同样，Speed:20是20rad/s≈191rpm，Speed:100≈955rpm，避免把指令单位当rpm。

## 7. 下次的推荐调试顺序

1. **建独立4015配置**，保留2804参数与当前基线。先核对采样量程，再选供电、限流、对齐与保护。
2. **仅运行编码器控制**，确认相序、方向、零点、实际电流和目标速度响应；先空载再加载。
3. **核对原始采样**：三相零点、断电/上电变化、无削顶、VBUS连续、开关时刻与ADC窗口正确。
4. **HSO只旁路观测**：在一个稳定中等电频率下比较速度方向和电角误差，先不接管。
5. **估算磁链并复测**：在多个稳定转速、正反两个方向比较学习结果；若相差明显，先查比例/时序/参数，
   不挑一个“刚好能转”的结果直接固定。Learn是本项目稳态估算器，不是ST官方完整Profiler。
6. **检查资格过程**：H Gate/H Qual/H Jitter/H Reset，区别偶发小角度波动与持续偏差。
   测试记录不仅写“看起来OK”，还记录误差范围、磁链一致性与时序计数。
7. **空载稳定接管**：TRACKING且当前H Gate=OK时Use，确认CONTROL、Feedback=HSO。
8. **逐项增加动态测试**：小幅改速→大幅减速→到切换边界→Speed:0→重新起转→反转→加载。
   每次只改变一个主要参数，并保留失败前后的原始波形与H Lost。
9. **最后再调低速性能**：先获得可靠中速工作区，再逐步降低边界；不从追求零速/拔掉编码器开始。

HSO独立方案和ZeST配合零速方案应区分；当前工程没有集成ZeST、PolPulse或完整的脱离编码器启动策略。
参见 [ST HSO/ZeST说明](https://www.st.com/content/st_com/en/ecosystems/stm32-motor-control-ecosystem/stm32-zest-and-hso-solutions.html)。

## 8. 每次试验最少记录这些数据

```text
固件版本 / 电机完整型号 / 极对数 / 母线电压 / Curr Loop开关
Rs / Ls / 物理磁链Wb / Filter Pole与Delay / 速度目标及单位
Speed 与 H Speed
H Error 的范围（可用JustFloat通道19记录原始rad误差）
H Flux 与 H Actual
H Gate / H Qual / H Jitter / H Reset
H Time 最大值及超时计数 / ChipRev
Feedback / Drive / H Lost
若电流异常：I Trip + IU/IV/IW R/Z
本次改动 / 成功条件 / 首次失败动作 / 是否重复可复现
```

屏幕刷新慢于控制循环，不能靠屏幕偶尔显示OK就排除短时越界。
H Time是控制回调测量值，不涵盖所有中断进入延迟或PWM预装载截止时间；保持低于100µs只是必要检查之一。
低层故障后先看原始采样和首因，高层失锁后先看H Lost，不用停机后的正常电流倒推运行期间没有异常。
