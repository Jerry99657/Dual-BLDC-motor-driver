# 通用六步油门：UI-R70-ESC

R72 界面入口更新：六步开关位于 `Settings → System → Sensorless → Six Step`，诊断位于 `Status → Six Step`。ESC Auto 的选择仍在 `Settings → Motor`，详见 [R72 UI](UI_R72_sensorless_menu.md)。下文保留历史实现与验证记录。

本文保留 R70 的实现与验证记录。当前 **UI-R71-ESC** 已将两套预设的六步启动信号资格与 ESC 统一；原文中的“预设固定 20 Hz／较低交接门槛”属于历史实现。新增实板反馈、20% 油门对照和当前固件资源见 [R71 启动资格](Six_step_capture_R71.md)。ESC 的入口、油门／Hz 及保存规则继续有效。

2026-10-25。本版增加 `Settings → Motor → ESC Auto`，仅用于 **Single M1 的六步无感驱动**。通用模式不填写极对数、Rs、Ls、KV 或磁链，使用 0～100% 油门和电气频率 Hz。2804／4015 预设继续提供机械速度 Speed 模式；原有编码器 FOC、独立 HSO、双机有感、主从、存储与保护保留。**无需重新配置 CubeMX，本轮未改变 SPI1／SPI2 的通信配置。**

## 操作

1. 停止电机，等待有效静止采样持续至少 200 ms。
2. 在 `Settings → System` 选择 `Single M1`，开启 `Six Step`。
3. 在 `Settings → Motor` 选择 `ESC Auto`，确认 `ESC Auto? / Throttle only`。其他工作方式下此选项不可用。
4. 回到 Run，应显示 `M1 Throttle ESC`；先用电机适用的母线电压、空载、30% 油门复测。上下键调节，OK 提交。KEY1 全局停止，KEY2 停止并返回。
5. 停止后等待 `Saved` 再断电。重启恢复 ESC 选择和油门偏好，但不自动运行。

Run 显示 `Est … Hz`；Status 的六步速度、Motion 速度也使用电气 Hz，机械 rpm 显示 `--`。没有极对数不能准确换算机械 rad/s 或 rpm。通用模式中左右短按不再切换到 Speed／Position，也不会因此停止输出；原长按左右切轴规则保留。

选择 `2804` 或 `4015` 即退出 ESC Auto，恢复该预设的 Speed／Throttle 选项。切换会清空运行目标，不会自动启动；原型号及极对数仍用于返回 FOC／HSO 后的控制。两套预设的六步 Speed 范围、原 Speed Limit 设置继续有效。

通用油门的请求电压为 `0.85 × VBUS × 油门百分比 / 100`，因而 30% 油门对应名义 25.5% PWM 占空比；电流约束还可降低实际 Duty。0% 为撤销输出、滑行停止。串口使用原 `Throttle` 命令；通用模式拒绝非零 `Speed` 命令，避免把未知极对数下的电频率冒充机械速度。

## 起转及接管

参考 [AM32 的启动与换相实现](https://github.com/am32-firmware/AM32/blob/main/Src/main.c)及 [ST 六步启动／采样排障说明](https://wiki.st.com/stm32mcu/wiki/STM32MotorControl%3A6-step_-_Optimization_and_troubleshooting_of_sensor-less_firmware_parameters)，保留“先起转、再依据实际反电势换相”的阶段划分。本项目自行实现电流辅助启动，没有移植完整 AM32，也没有假定任何电机都能使用相同的启动功率。

通用模式流程为 `ALIGN → SINE → SYNC → RUN`：

- **ALIGN**：固定电流矢量；Id 在 400 ms 内升至 0.25 A，Iq=0，对齐 1 s。电流跟踪失败仍停机。
- **SINE**：不用编码器，10 kHz 推进电流角，按 20 电气 Hz/s 加速。至少达到 12 电气 Hz；尚未达到强度要求时继续升频，最高 60 电气 Hz。
- **稳定资格**：使用滤波后的电流误差和 `|Uq|` 强度代理。至少达到 12 Hz 且 `|Uq|` 达到 0.7 V 后暂停升频，避免较大磁链的电机提前冻结在接管下限以下；强度至少为 `max(0.6 V, 0.01 × VBUS)`，电流跟踪合格，并连续保持 500 ms，才允许进入 SYNC。电流误差滤波约 5 ms；强度滤波约 100 ms。
- **SYNC**：在正确电角边界切换为两相导通、一相悬空；交接电压为 `√3 × (|Uq| + 0.2 × |Ud|)`，采用实际启动控制电压，不查询电机 Rs。此后由实际反电势过零安排换相。
- **RUN**：必须连续通过 12 次真实过零资格，才开放最终油门请求。通用模式不使用预设速度 PI。

这里的 `|Uq|` 包含电感压降，是启动强度代理，**不等同于纯反电势，也不能单独证明转子已经跟上**。因此仍须通过真实过零。没有扩大相位窗、相邻周期比或丢过零超时来制造 RUN：相位窗保持 10～85%，相邻周期比保持 55～145%，TIM7 丢过零看门狗、滞回及退磁屏蔽保留；整个启动最多 8 s，失败不自动重启。

R67 的自适应采样保留：实际 Duty 低于 25% 使用峰顶 OFF，高于 30% 使用谷底 ON，中间保持原选择。仅 Single M1 六步 SYNC／RUN 改变 CH4 采样中心；10 kHz PWM、双 ADC 注入顺序、VREFINT／VBUS 连续采样及其他控制方式的采样中心不变。

本轮也更新了 **2804／4015 预设共用的六步起转环节**：启动电流 PI 统一为 P=0.2、I=120，改用滤波电流误差和实测 Ud／Uq 交接。预设的启动电流仍为其额定电流配置的 50%，起转目标仍为原 20 电气 Hz（Speed 目标更低时随目标）；没有改变编码器 FOC 或 HSO 的电流 PI。两套预设也需要实板回归。

## 电流、频率与保存边界

通用模式采用本板的保守策略，避免继承隐藏型号的额定电流和电压：

| 项目 | ESC Auto |
| --- | ---: |
| 启动 Id | 0.25 A |
| SYNC 相电流幅值约束 | 0.30 A |
| RUN 相电流幅值约束 | 0.50 A |
| 任一相瞬时软件过流 | 2.0 A |
| 持续过载基准／超额平方电流预算系数 | 0.8 A／3 s |
| 当前六步电气频率上限 | 200 Hz |

幅值约束不等于精密稳流，瞬时保护和过载预算独立生效。COMP4 → TIM1 Break 硬件 IBUS、Settings 中的 DAC 阈值、ADC 合法性、VREFINT 换算、KEY1 停止均保留。电机仍须使用合适的供电和功率范围；通用模式不会识别电机额定电流，也不保证所有电机、负载或极低速都能成功起转。200 Hz 上限来自本项目当前采样及检测范围，不代表穿越机电调的高速能力。

保存仍使用原 v3 记录：control_config 的空闲 bit15 为 ESC 偏好，bit14 为 Six Step，结构长度和 CRC 未变。旧记录 bit15=0，沿用原预设。关闭六步、切到 HSO／编码器或双机时不应用 ESC 算法，但保留其偏好，回到 Single M1 六步时恢复；明确选择 2804／4015 才清除 ESC 偏好。M2 的型号选择不会修改 M1 的 ESC 偏好。

JustFloat 仍为 25 路：通用模式通道 0 为油门%，1／7 改为电气估计／参考 Hz，23 为 0（油门）；原六步 8～13 的最近六个周期仍为 ms，16～21 的 Duty／残差／扇区／连续数／累计数／状态不变。使用遥测的上位机需依据工作配置解释 1／7 的单位；预设模式继续是机械 rad/s。

## 这次诊断的证据边界

用户的 2804 记录是 SYNC 后 `NO ZC`，仅 2/12 次有效过零，Duty 7.9%，Start EMF 0.42 V。说明已通过旧启动资格，但实际过零未持续建立；仅凭这些数字不能断定唯一原因是转速、电流交接还是采样误差。本轮没有在实板复现该故障。

检查确认旧六步启动依赖预设 Rs／Ls／额定电流；原始逐帧电流误差资格还会受 PWM 波动影响。在本轮名义 2804 耦合模型中，旧 R69 因稳定资格被反复打断，最终 START TIMEOUT；这与用户的 NO ZC 并非同一故障现场，不能宣称复现了其确切根因。

曾测试将完整 Ud 计入交接电压，4015 模型出现反转及较大电流，已弃用。最终只保留 0.2 × 实测 Ud 的交接贡献，并保留全部真实过零判据。模型通过用于排查软件和明显不合理的候选方案，不能代替实板测量。

## 验证记录

`tests/motor_host/run.py`、`tests/ui_host/run.py`、`tests/usb_host/run.py` 及 Debug／Release 的链接后启动检查均通过，覆盖原 FOC／HSO／双机／主从／保护／编码器／SPI2 Flash，以及新 ESC 选择、确认取消、持久化、机械速度拒绝、电气 Hz、字体和按键操作。HSO 官方二进制在主机行为测试中使用桩，不代表实机观测性能验证。

独立电气／机械耦合模型使用实际电流、转矩和运动推进转子，不预设转子必然跟随强制角。物理电机与控制器底层保存的型号分别选择；通用模式下两种底层预设得到相同结果：

| 物理模型／母线／油门 | 末段实际机械速度（仅模型可知） | 电气频率约值 | 最大相电流 |
| --- | ---: | ---: | ---: |
| 2804／12 V／30% | 72.58 rad/s | 80.86 Hz | 0.310 A |
| 4015／12 V／30% | 21.72 rad/s | 38.02 Hz | 0.325 A |
| 4015／20 V／30% | 36.15 rad/s | 63.29 Hz | 0.387 A |

各场景 9 s 内进入并保持 RUN，无反转；每项都分别以底层保存 2804 和 4015 运行。堵转按 8 s 启动超时停机，无电流反馈在对齐期停机，KEY1 在 SINE 立即停机。原 4015 预设的 12／20 V、正反转 Speed、低速及降油门模型回归继续通过。

模型假设：2804 Rs=2.3 Ω、Ls=0.86 mH、7 极对、磁链 3.2 mWb、惯量 5×10⁻⁶ kg·m²；4015 Rs=1.8 Ω、Ls=1.3 mH、11 极对、磁链 7.5 mWb、惯量 2×10⁻⁵ kg·m²；两者黏性摩擦系数 3×10⁻⁵ N·m·s/rad。这些参数未经本次实物辨识，特别是三角形电机的等效参数口径仍需实测确认。

## Flash 空间优化与交付

为容纳新增功能，`compact_div64.c` 以完整范围的 64 次恢复除法替换 GCC 的 `__udivmoddi4`。链接体积从 760 B 降为 82 B，节省 678 B；仅 UART 初始化和 UI 动画的 64 位除法使用，电机／HSO 控制计算不使用此函数。保留 libgcc 的有符号／无符号 ABI 包装，保留全部功能、字体与 Debug 符号。

验证包括主机全范围边界和 10 万组随机商／余数对照，以及 Unicorn 执行实际链接的 Cortex-M4 Thumb 机器码，对照 `__udivmoddi4`、`__aeabi_uldivmod`、`__aeabi_ldivmod` 的寄存器调用约定与结果。测试覆盖非零除数；除零及有符号最小值除以 −1 不属于 C 调用契约。可选 ARM 验证脚本为 `tests/motor_host/check_div64_arm.py`，需要 Unicorn 和 pyelftools。

Debug／Release 均构建成功：**Flash 131040 / 131072 B，余 32 B；RAM 23112 / 32768 B**。保留原 RWX LOAD 段链接警告。ELF 导出的二进制与交付 BIN 一致；未烧录或执行实板电机测试。
