# R80：用户代码体积优化，第 1～3 批

固件版本 `UI-R80-SZ`。本轮只做基线、体积优化和必要验证，未加入后续功能。无需重新配置 CubeMX。

## 实际结果

| 阶段 | Debug Flash | Release Flash | 剩余 Flash |
| --- | ---: | ---: | ---: |
| R79 基线 | 131064 B | 131064 B | 8 B |
| UI 应用层重构 | 131044 B | 131044 B | 28 B |
| 用户控制与服务代码优化完成 | 130164 B | 130164 B | 908 B |

最终净节省 **900 B**。链接器统计的 RAM 占用从 23112 B 降至 23096 B，包括 RAM 中的代码以及链接脚本预留的堆、栈区域。

此次未达到“释放数 KiB”的预期目标。工程此前已有较充分的 LTO、格式化和字体优化；后续功能仍需逐项计算体积，908 B 不能作为所有规划功能的预算。

## 已完成的修改

1. **基线和边界检查**：增加 `tests/flash_report.py`，保存 Debug/Release 的 ELF、BIN、map、用户源码、函数大小排名、资源占用和散列值。核对 205 个官方/核心/生成文件及其编译命令。基线与分阶段报告位于被 Git 忽略的 `build/size-baseline/`，原始基线不会被覆盖。
2. **UI 应用层**：将长期持有的动态文本集中管理，使用每行 4 B 的静态描述更新同类诊断值；增加直接输出定点数和单位的 `UiText_Fixed`，避免临时数字字符串及重复格式解析。描述项只负责显示值，不引入控件树、业务回调表或动态分配。
3. **用户控制代码**：将采样、M1 私有状态、双轴协调状态分别集中存放，减少链接结果中的地址加载与常量池开销。轴状态仍然独立，原有 `volatile` 限定、计算顺序、保护条件和参数保留。
4. **公共用户函数**：共用 PID 初始化/复位及编码器错误分类处理。M1 与 M2 的错误总数仍写入各自原来的计数器，M2 的计数访问保留 `volatile`。
5. **低频参数访问**：仅在用户 `motor_params.c` 中保留实测有收益的 ARM/GCC 大小优化设置。HSO 热路径、ST 算法库和数学计算保持原设置。

UI/协议已经共用 `MotorControl_*` 入口，设置也已有 KK_UI 静态绑定。本轮继续使用这些入口，未增加另一套通用分派框架。

## 已撤回的试验

- 对其他低频用户模块全面使用 `-Oz`：结果为无收益或增大。
- 给更多 UI 函数强制禁止内联/克隆：结果为无收益或增大。
- 单独抽取存储 A/B 加载函数：LTO 已能充分共享，净收益不明显。
- 合并 HSO 外围、辨识、六步及编码器的私有状态：部分布局反而增大，均已恢复。

没有修改 ST/HAL、CMSIS、USB 官方库、ST HSO 源码/静态库、KK_UI/KK_OLED 核心、CubeMX 生成文件、链接脚本或它们的现有编译命令。没有删除字体、图标、页面、算法、保护或保存字段。

## 验证

- Debug/Release 均完成干净构建；最终 ELF/BIN 一致，启动/MSP、ADC/TIM、硬件 Break、KEY1 全局停止及 TIM7 链接检查通过。
- 电机主机回归通过：双轴/主从、两套预设、FOC、HSO、六步及独立电机模型、辨识、采样/IBUS/全局停止、编码器恢复/SPI2 仲裁、协议和数字解析。
- UI、存储、LCD、USB CDC 主机回归通过；新增定点格式化与标准库结果比较，覆盖正负边界、0～3 位小数、单位及截断边界。
- 65 组已有界面静态帧/动画记录与基线逐字节一致；最终版本仅更新 About 的 FW 字符串。
- 三份控制源码的状态布局重排前后，对消除访问前缀后的 21996 个控制代码标记进行比对，计算及分支语句一致。

尚未烧录开发板验证。主机测试和静态比对不能替代实板控制耗时检查；烧录后重点复测普通启停、双轴/主从、HSO 和六步启动，并观察 `Ctrl Max`。

## 使用报告脚本

```powershell
# 后续优化建立新的基线目录，不覆盖 R79 基线。
python tests/flash_report.py baseline --directory build/size-next

# 编译两个配置后，与对应基线比较。
cmake --build --preset Debug
cmake --build --preset Release
python tests/flash_report.py final --directory build/size-next
```

报告脚本读取已有构建结果，调用前必须确保源码与 ELF 同步。不要用保留旧时间戳的源码复制来替换源码后直接比较；必要时做干净构建。
