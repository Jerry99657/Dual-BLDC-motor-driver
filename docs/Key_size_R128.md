# R128：按键修复的体积审计与精简

固件 `UI-R128-KEY`，Native 回执编号 128。基线为 R127，全部原有功能及保护保留，不修改 ST 官方库或初始化配置。

## 624 B 的来源

R126 已用 Flash 130096 B、剩余 976 B；R127 已用 130720 B、剩余 352 B。增加 624 B，消耗当时约 64% 的剩余容量。

保持 R127 输入实现，单独恢复 R126 的 SPI 用户驱动后重链接，Flash 为 130624 B。因此在这个构建顺序下：

| 分组 | 链接镜像净增 |
| --- | ---: |
| 1 kHz 按键采样、短按保留、上下文取消、防重放、松开序列及应用接入 | 528 B |
| LCD DMA TC 后 FIFO 尾部收尾 | 96 B |
| 合计 | 624 B |

这是分组 A/B 构建的净差。LTO 会改变函数内联、文字池和布局，不能将两组数字解释为某个源码函数的独立大小。例如符号表出现更大的 `MX_I2C3_Init`，同时 `main`、`MX_DAC3_Init` 变小，是内联边界移动；官方源文件和编译选项没有因此新增或改变。

短按保留需要新增状态与交接路径，防止“停机后交付旧按键而重新启动”等行为也需要处理。但上一轮把独立的 LCD 问题和按键修复一起交付，体积控制不足。此前的优化仍在；新增机制消耗了它们释放出的空间。

## 本次保留的精简

1. 合并上下文更新与按键消费的受保护状态发布，复用屏蔽中断、恢复 PRIMASK 及部分状态处理。上下文仍由主循环管理，ISR 仍只采样与记录。
2. 合并松开序列的重复分支。保留按住不重复执行、两次松开样本后再交付下一次按下，以及故障／轴／模式变化时取消旧输入。
3. 当 CubeMX 将六个 UI 按键配置在同一个 GPIO 端口时，一次读取 IDR，按生成的引脚宏映射为 UI 键值。端口不同时自动使用原有逐键读取，低有效／高有效选择仍受支持。KEY1 保持 EXTI 全局停止。

前两项合计净回收 32 B，端口读取精简再净回收 40 B。消抖时间、输入过期时间、外环调度和保护门限不变。LCD 收尾修复保持 R127 实现。

## 最终资源

Debug、Release 均执行清理重编译；以下为实际 ELF／BIN 镜像结果。

| 项目 | R126 | R127 | R128 |
| --- | ---: | ---: | ---: |
| Flash 已用 | 130096 B | 130720 B | 130648 B |
| Flash 剩余 | 976 B | 352 B | 424 B |
| RAM 已分配 | 30936 B | 30960 B | 30960 B |
| RAM 剩余 | 1832 B | 1808 B | 1808 B |

本次净回收 **72 B**。相较 R126 仍净增 **552 B**，没有回到修复前的体积。试验过的 ISR 聚合状态、禁止内联、整文件 Oz、状态字段复用等组合没有更好的镜像结果，未保留。不同改动的净收益受 LTO 组合影响，不能直接按源码行数推断。

## 验证

- 用相同 UI／控制夹具分别编译 R127 和 R128 的输入模块：短按、确认／停止、长按、松开、故障／轴切换、对齐、设置和整页交互的回归输出一致。
- 六个物理键的全部 64 种组合；共享端口／分散端口、重新分配的引脚、三种有效电平掩码均通过。共享端口每次一次 IDR 快照，分散端口逐键读六次。
- 68 组 UI 图像／帧流、64857 次文字绘制、870 行诊断与 R127 一致，仅固件标识归一化。
- Cortex-M4 实际链接代码的 10 组消抖／保留／过期／回绕用例通过。在同一初始非运行外环模型中，R127 为 326～362 条指令，R128 为 275～309 条；这是含外设／查询边界替代的模型计数，不是板上微秒或周期测量。
- Debug／Release 的启动、真实外环保护路径、协议／JustFloat、HTML 控制台及真实 Edge 串口格式／断线恢复回归通过。
- 207 个受保护文件的哈希及官方／Core 编译命令与 R127 基线一致。没有调整官方库、CubeMX 初始化或编译选项。
