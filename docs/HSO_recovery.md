# UI-R19-45RPM：按机械转速选择减速反馈

## R19 当前减速策略

用户要求 HSO CONTROL 期间高于 45rpm 的正常减速继续使用 HSO，撤销 R18 的大幅改速提前返回。

- 切换点为机械转速 **45 rpm = 4.712389 rad/s**，当前 7 极对对应电频率 **5.25 Hz**。
- HSO 接管完成后，电角度和速度闭环直接使用 HSO 输出；编码器保留安全校验和切换边界测量。
- 高于 45rpm 时，改变目标速度的幅度不会触发正常退出。例如 100→20 rad/s 全程可保持 HSO。
  注意 Speed 指令仍为 rad/s，Speed:20 约为 191 rpm，明显高于切换点。
- 目标低于 45rpm（含 Speed:0）时，先由 HSO 执行减速，实测速度到达 45rpm 才开始约 10ms
  返回编码器的过渡，再由编码器继续控制到原目标。不会收到 Speed:0 就立即返回。
- 反转同样先由 HSO 减至该绝对速度边界，再返回编码器经过零速进入反向。
- 判断边界用健康编码器的实测机械速度，避免等 HSO 低通速度追上时已经跌破观测器 5Hz 门限。
  这条测量仅用于选择反馈源，不作为高于边界时的速度环反馈。
- 手动 HSO:Use 保留资格检查，实测速度和速度模式目标须严格高于 45rpm、且方向相同；
  撤销 R17 的 10Hz 接管限制。低速退出后仍由操作者在条件满足时再次 Use，不自动重新接管。
- HSO 减速参考斜率设为 50 rad/s²，编码器减速仍为 150 rad/s²，正常加速为 100 rad/s²。
  理论上参考从 100 降到 20 rad/s 约需 1.6s，实际转速响应取决于负载与控制效果。
- ANGLE、采样、过流等真正异常仍按停机保护处理，不因要求维持 HSO 而跳过校验。

协议+FOC 主机测试已覆盖高于边界的大幅改速、HSO 减速斜率、目标为零但实际仍高速时不退出、
45rpm 边界与低通速度滞后、正/反方向、反转先减至边界、真正异常停机及显式命令恢复。
这些是逻辑验证；ST 观测器仍由主机替身模拟，实际低速观测能力和减速稳定性需上板验证。

## R18 改速修正（历史，大幅改速提前返回已撤销）

用户反馈 HSO CONTROL / Speed:100 后，第一次 Speed:20 停转，第二次才起转。
源码存在两条会覆盖新目标的路径：100→20 仍高于低速退出门限，减速中的观测失效会清零新目标；
或命令执行时失锁已待处理，随后 ADC 回调才执行停机，覆盖刚提交的目标。
用户进一步确认首次停转后 H Lost=ANGLE、Feedback=ENCODER、Drive=READY，
与角度失锁后清零目标、退回健康编码器待新指令的路径吻合。

- HSO 速度模式下，大幅目标调整先开始正常的 10 ms 编码器返回，再提交新目标；不等待减速导致失锁。
  大幅调整门限为 `max(10 rad/s, 20% * max(|旧目标|, |编码器速度|))`，比较新旧目标差绝对值。
  100→20 满足此门限，100→95 不满足，后者继续 HSO。门限是本项目试验策略，非 ST 算法性能保证。
- 速度提交前先处理已经待定的 HSO 故障，再将这条明确的新命令作为恢复/改速命令提交，
  防止命令提交后的下一次中断再用旧故障清零新目标。
- 这段提交使用短临界区，避免中断介入正常返回与目标写入之间。
- Run 页调整为先设置控制模式、再设置目标，与串口顺序一致；停机后第一次 Run 确认也能执行恢复。
- 低速、反转退出与真正失锁后的无命令不重启规则仍保留；底层保护不会被改速绕过。

真实协议+FOC 测试增加小幅改速保留 HSO、首次 100→20、返回期间角度失效、
命令到达前已存在失锁等场景。观测器仍由主机替身模拟，尚未实板验证。

修复旧版 `HSO:Use -> Speed:0 -> HSO LOST -> Speed 无法重新起转` 的交互。
正常减速不再沿用异常失锁锁存；真正失锁也不要求先发送一次 Stop 才能重新执行 Speed。

## 正常控制

- 默认由 MT6701 控制；HSO 持续旁路观测，已学习的磁链保留在 RAM 中。
- HSO 接管保留 R16 资格校验，并要求实测速度及速度模式目标 >45rpm 且同向。
- 接管后在实测绝对速度 <=45rpm 时返回编码器；目标值降低或反转本身不触发提前返回。
- 45rpm 对当前 7 极对电机为 5.25Hz 电频率，略高于观测器 5Hz 资格门限。
- 正常返回保留速度/转矩目标、控制模式和速度斜坡；角度修正与速度修正用约 10 ms 收敛到编码器。
  因此 Speed:0 继续按速度斜坡减速到零；新的 Speed 指令可继续启动。Stop 仍用于清零输出目标。
- 返回使用**实时编码器角度 + 逐步衰减的上一有效相位修正**，不冻结转子角度，
  也不继续使用已失效的 HSO 角度/速度。
- 返回期间仍检查采样、编码器及控制时序；真实错误立即转入下面的异常停机。
- 正常低速退出不产生 H Lost，不自动调用 Learn，不清除磁链。
  Learn 只用于稳定旋转时的参数估算，不能作为零速运行状态。

## 真正失锁

ANGLE / FREQUENCY / FLUX 等异常导致资格撤销时：

1. 退出 HSO，清零速度和转矩目标、PI 状态，转为零输出停机。
2. 加入输出禁止状态，观测恢复或编码器恢复本身不会重新驱动。
3. 编码器和采样健康时，反馈状态回到 ENCODER、Drive 可为 READY；
   **新的有效 Speed 指令**释放该停机状态并使用编码器起转，无需先 Stop。
4. 编码器异常时显示 STOPPED，恢复健康后也需要再次明确发出运动命令。
   异常期间缓存的命令不会在恢复时自动执行。
5. MotorSampling 的 ADC、电流、过载、母线等底层故障仍按原规则锁存；
   Speed 不会清除这些故障。应排除原因并按原规则复位。
6. 下一次通过资格后可以再次 HSO:Use；HSO 不会自动接管。

Angle/Position 或非零 Torque 新命令也可在反馈健康时释放 HSO 停机状态。
Speed 的解析新增完整有限数校验；NaN/Inf/空值/尾随垃圾不会更换模式或释放停机。

## 状态与试验

- `Feedback`：ENCODER / HSO / TO ENCODER / STOPPED。
- `HSO`：接管为 CONTROL，过渡为 RETURNING，退出后显示旁路观测状态。
- `H Lost`：上次真正失锁的首次原因，Stop/Speed 后仍保留用于核查；下一次成功 HSO:Use 清除。
  H Lost 有内容不代表驱动当前仍被锁住，要结合 Feedback 和 Drive。
- Drive 优先显示真实采样/母线/电流故障，不再被连带的 HSO 停机提示掩盖。
- JustFloat 格式仍为 25 通道；24 通道 0=编码器，1=HSO（含返回过渡），-1=HSO 异常后因反馈不健康阻止驱动。

建议回归顺序：编码器 Speed:100 -> HSO:Learn（需要时）-> TRACKING 且 H Gate=OK ->
HSO:Use -> CONTROL -> Speed:0 -> ENCODER -> Speed:100 -> 再次 HSO:Use。
还应测试正反转、手动加载后停机、新命令恢复和真实硬件故障阻止启动。

主机验证现已将真实协议解析与真实 FOC 链接到同一测试，覆盖上述命令流程、
低速/反转返回、无效 Speed 拒绝、失锁后无命令不重启、首因保留、
编码器/采样故障不能被新命令绕过、ADC 回调结束时发现超时即撤掉输出。
观测器边界仍为主机替身，未实板验证机械过渡、制动效果、回馈电压或 ST 算法精度。
