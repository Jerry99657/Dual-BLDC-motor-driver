# UI-R42-ENCRETRY：ENC2 自动重连与 APB 时钟恢复

本页保留 R42 的重连和时钟设置；当前 R43 全部保留，并增加全零事件前后角度诊断。当前烧录标识、资源及新诊断见 [Encoder_zero_event_diagnostics.md](Encoder_zero_event_diagnostics.md)，下文 R42 构建数据为历史记录。

本版根据用户确认的策略区分“未启用的可选 ENC2”和“当前模式所需的 ENC2”，保留 R41 的 E1/E2 诊断和 M1 DMA 超时恢复。控制增益、主从跟随算法及电流保护均不变。

## ENC2 探测与恢复

| 情况 | 连续实际失败 5 次后的行为 |
| --- | --- |
| Single M1，ENC2 未启用 | 停止探测并释放 SPI2；显式 Retry、启用 M2 或 MCU 复位后才允许重新尝试 |
| Single M2 或任一双电机模式 | 等相关输出/跟随停止并释放 SPI2 预留后，每 250 ms 最多探测一帧 |
| Flash 持有总线、SPI2 忙或 W25Q64 片选为低 | 跳过探测，不增加失败次数，也不消耗本次探测间隔 |
| 重试帧有效 | 清除连续失败次数，恢复 10 kHz DMA；累计错误和最后错误仍保留 |
| 重试帧无效或超时 | 保持五次失败锁定，下一次仍间隔 250 ms；不会重新突发提交五帧 |

低频探测复用主循环已有的单帧轮询，HAL 超时参数为 1 ms，中断保持开启；ADC 中断不会对这类轮询执行 DMA 看门狗。迟到的 DMA 完成/错误回调也不能释放轮询正在使用的片选。恢复不预留运动总线、不写运动目标、不使能功率输出。

相关控制层仍在反馈失效后停止输出；恢复通信不会恢复之前的 Run/Follow。启动时 ENC2 达到五次失败锁定也会取消等待中的自动对齐，避免接回后自行通电。M2 作为通电电机失联时取消对齐，恢复后仍需手动 Align / Retry，再启动。M2 为被动手转主机时不通电对齐，健康并等待估计稳定后可手动重新 Follow，建立新的跟随锚点。

已有手动入口继续保留：停止后在 Settings → System 中选择 View M2，再执行 Align / Retry；串口为 `Align:M2`。被动主机只重试编码器；通电轴的 Align 会执行对齐。

E2 Age 仍为当前/历史最大采样周期数。显式 Retry 设置的“尚无新样本”哨兵值不会直接污染历史最大年龄；真实长时间失联的年龄仍可累积至 65535。`ALL 0` 的真实零角度歧义仍保留，未通过忽略 CRC、磁场或超时来掩盖掉线。

## 时钟恢复及其他外设速率

已同步 `FOC_two.ioc` 和初始化代码，本轮无需再手动操作 CubeMX。APB1/APB2 恢复为 /1、170 MHz；CPU/AHB 仍为 170 MHz。

| 外设 | 本版配置 | 结果 |
| --- | --- | --- |
| ENC1 / SPI1 | 170 MHz /256，Mode 1 | 664.0625 kHz，24 位纯线传输约 36.14 μs |
| ENC2 / SPI2 编码器事务 | 临时切 Mode 1、/256，完成后恢复 CR1/CR2 | 同为 664.0625 kHz |
| W25Q64 / SPI2 默认事务 | /8，Mode 0 | 保持 21.25 MHz |
| LCD / SPI3 | /16 | 保持 10.625 MHz |
| I²C3 | 保留 SYSCLK=170 MHz 和 TIMINGR=0x40B285C2 | 时序不变 |
| FDCAN | 保留 PLLQ=170 MHz 及现有位时序 | 通信速率不变 |
| USART1 | PCLK2=170 MHz，HAL 按 115200 重新计算 BRR | 保持 115200 baud |
| USB CDC | HSI48 + 原 CRS | 保持 48 MHz |
| TIM1/8、TIM2、TIM3、TIM6 | APB /1 后定时器内核仍为 170 MHz | PWM 10 kHz、外环 1 kHz、WS2812 和规则采样时基不变 |
| ADC1/2 | HCLK/4 | 保持 42.5 MHz |

今后重新生成时，保留 APB1/APB2=170 MHz、SPI1 /256、SPI2 默认 /8、SPI3 /16，以及 I²C3 SYSCLK、FDCAN PLLQ 和 USER CODE。不要只恢复 APB 而遗留 R39 的 Flash /4、LCD /8。

## 验证与上板检查

主机测试覆盖：可选 ENC2 缺失/超时五次停止及真实 W25Q64 保存读回；启用 ENC2 后的 250 ms 单帧探测、输出预留和 Flash/忙总线跳过、轮询超时、ADC 抢占、迟到 DMA 回调、有效帧后恢复 DMA、模式启用/禁用切换、tick 回绕、恢复不自启及手动对齐。原 M1 DMA 恢复、控制保护、UI/LCD 和 USB 回归继续执行。时钟检查从初始化代码计算频率并与 `.ioc` 核对。

烧录 Release ELF/BIN 后，确认 About → FW 为 **UI-R42-ENCRETRY**。当前 M2 手转主机/M1 从机的测试重点：故障使跟随停止，E2 在恢复接线后自动恢复有效采样，电机保持停止；再手动按 OK 或发送 Follow 启动。未启用 ENC2 时，故意断开后累计新增错误应停止在五次实际失败。

电机/采样/保护/编码器/存储、UI/LCD、USB 主机测试均通过；Debug/Release 构建、强 IRQ/MSP、启动顺序、ELF/BIN 一致性及 `.ioc` 时钟检查通过。Debug：Flash **131012 / 131072 B**，余 **60 B**，RAM **21704 B**；Release：Flash **130236 B**，余 **836 B**，RAM **21616 B**。保留已有 RWX LOAD 链接警告，未再调整编译优化选项。

本轮没有烧录或驱动实际电机，软件回归不能确认 PWM 干扰的电气根因，也不能代替实板通信波形和控制执行时间测量。
