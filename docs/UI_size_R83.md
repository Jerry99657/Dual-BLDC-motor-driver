# R83：UI 应用层体积优化

固件 `UI-R83-SZ`。在保留全部页面、字体、字号、图标、动画、按键和诊断字段的条件下，只优化 `mycode/ui_app.c` 与 `mycode/ui_text.c`。无需修改 CubeMX。

## 实测结果

| 链接占用 | R82 基线 | R83 | 变化 |
| --- | ---: | ---: | ---: |
| Debug／Release Flash | 130476 B | **130252 B** | 减少 **224 B** |
| Flash 剩余 | 596 B | **820 B** | 增加 224 B |
| RAM 分配（含预留堆栈） | 23144 B | **23192 B** | 净增加 **48 B** |

本轮收益仍是几百字节。此前 UI、KK_UI 和绘图代码的约 28.36 KiB 归属统计包含实际功能，不能视为可直接回收的空间；820 B 也不足以容纳较大的新功能。

## 保留的实现

1. **快照读取减少复制**：需要完整值的 UI 路径直接调用控制器的输出参数接口，写入各自局部快照；立即查询单个字段时共用主循环内的临时快照，减少结构体返回引起的复制。临时指针不跨下一次读取保存，UI 也不在中断中调用此接口。
2. **复用同一状态**：刷新 Drive 文本和记录停机原因时，使用当前已经获取的快照，避免再次读取。Run Steps／Detect 绘制不再读取未使用的电机快照。
3. **内部文本布局**：将经常访问的短缓冲放在更容易寻址的位置，保留每个缓冲原容量。这个私有布局没有写入 W25Q64，也不改变保存记录。
4. **诊断描述压缩**：静态描述由 4 B 压缩为 3 B：12 位文本偏移、4 位格式、8 位源偏移。逐字节解码，避免非对齐读取；编译期检查缓冲总长度、源偏移和格式范围。
5. **整数转换共用**：定点数和整数／十六进制格式化共用数字提取函数；保留负数、补零、小数位、单位、截断和返回长度语义。

各次对照构建的实际 Flash：

| --- | ---: |
| R82 基线 | 130476 B |
| 复用已有状态 | 130444 B |
| 文本缓冲布局 | 130436 B |
| 单字段查询快照 | 130316 B |

这些增量受整个 LTO 链接结果影响，不能外推为独立函数的固定节省量。

已撤回无收益或增大的试验：强制禁止字符输出内联（无变化）、共用右对齐绘图包装（增加 40 B），以及其他文本布局方案。

- 应用格式化对照测试通过，包含定点数、符号、十六进制、补零、边界值和缓冲截断。
- UI、按键／连按／长按切轴、Run 确认、远程来源保护、参数编辑、保存／恢复、LCD 真实驱动及异常恢复测试通过。
- **版本号更新前，62 张已有静态／过渡截图与基线逐字节一致**。最终只在 `about.pgm`、`about-transition.pgm` 中出现 FW 文字变化；其他图像相同。UI 测试完成 3689 次显示提交。
- LL 中断全组合／真实采样保护集成、USB CDC 测试通过。
- Debug／Release 干净构建与链接启动检查通过，验证实际控制／HSO／辨识／Break／KEY1 路径、移除的通用 HAL IRQ 分发器、ELF／BIN 一致性。
