# UI-R40-ENCIO：运行后编码器报错的定位

本页记录 R40 的诊断。用户随后确认故障位于 M2 手转主机、Frame 停在 6，符合 ENC2 五次连续失败后停止探测；当前 R41 已将对应行明确标注 E1/E2，并增加 M1 DMA 超时恢复。当前固件及资源见 [Encoder_axis_dma_recovery.md](Encoder_axis_dma_recovery.md)，下文 R40 标识和构建数据保留作历史记录。

用户在 R39 / 332 kHz 上观察到：仅功率输出后发生 ENC1/2 ERROR，Ctrl Max=53 μs，Enc Age=1/5，Enc Frame=16；CRC、SPI、Field、Track 均为 0。ERROR 有时随后消失，能够再次发起 Run。

## 数据能说明什么

| 项目 | 当前实现中的含义 |
| --- | --- |
| Enc Frame=16 | 当前查看轴自复位以来有 16 帧收到全 `0x000000` 或全 `0xFFFFFF`，被现有策略拒绝；并不表示当前连续 16 帧失败 |
| Enc CRC=0 | 全零/全一判断先于 CRC，不能据此排除线路或供电异常 |
| Enc SPI=0 | HAL 未记录启动/传输错误，不保证 MISO 数据内容有效 |
| Field / Track=0 | 未记录通过 CRC 后的相应磁场状态异常；不是对所有被丢弃帧的磁场保证 |
| Enc Age=1/5 | 当前有效角度年龄 1 个调度周期、历史最大 5 个周期；右侧不是允许值 |
| Ctrl Max=53 μs | 已计时的控制区间最大 53 μs，低于 100 μs 门槛；不包含全部 DMA 回调排队或其他临界区延迟 |

实时编码器的样本年龄门槛为 3 个周期。历史达到 5，说明角度曾约 0.5 ms 没有有效更新，足以短暂显示 ERROR；这不是一帧 SPI 实际花费了 0.5 ms。

## 为什么会恢复

ENC1 在错误后仍按节拍采样。新帧通过验证就发布新角度、清零当前样本年龄，实时 Encoder 状态可恢复 OK；累计计数和最近错误原因保留。功率输出被故障处理关闭后仍须显式 Run，采样恢复不自动重启电机。

ENC2 在达到连续 5 次失败之前，也可由有效帧清零失败连计并恢复采样健康。一旦达到 5 次而停止探测，须显式 Retry/Align 或复位；有效通信恢复后，能否 Run 还取决于相应轴的对齐和保护状态。不能把 Encoder 显示恢复理解为所有停机原因已被自动清除。

## R40 的改动与限制

R39 的 `Enc Last=NO FRAME` 未区分全零和全一。本版仅将这两种错误原因拆为：

- `ALL 0`：收到 `0x000000`。
- `ALL 1`：收到 `0xFFFFFF`。

两类继续累计到原有 `Enc Frame`。`Enc Last` 仍保留最近一次错误，后续正常帧不会擦掉它；它只代表最近一类错误，无法给出两类各自累计数量。未增加中断内串口打印、未新增 UI 行、未改变通信速度、控制参数、重试策略和掉线保护。

有一个必须保留的歧义：按当前 CRC 算法，全零的角度、状态和 CRC 也能构成格式合法的零角度帧。因此 `ALL 0` 本身无法区分真实零角度、MISO 被拉低、器件未正常响应等情况。现有全零拒绝策略可能误判经过零角度的数据；本版继续保留原策略以避免未经确认就把断线/卡低当成健康反馈，并将这一限制明确展示。`ALL 1` 则不是正常健康角度帧。格式、状态及 CRC 范围参见 [MagnTek MT6701 数据手册第 26 页](https://www.magntek.com.cn/upload/pdf/202407/MT6701_Rev.1.8.pdf#page=26)。

## 下一步板上区分

“只在功率输出后发生”使编码器端供电下陷、地回流干扰、CS/SCK 毛刺及 MISO 受干扰成为优先怀疑对象，但尚不足以确定具体根因。SCK 降频不会同时降低功率桥的开关边沿，也不等同于降低 GPIO 输出边沿速度。ST 也指出 SCK 毛刺和重配置期间的输出处理会导致 SPI 失步，见 [AN5543 第 4.5 节](https://www.st.com/resource/en/application_note/an5543-guidelines-for-enhanced-spi-communication-on-stm32-mcus-and-mpus-stmicroelectronics.pdf#page=19)。

1. 烧录当前固件，确认 About → FW=**UI-R40-ENCIO**；在 Status 的 Axis 确认查看轴，复现后记录 `Enc Last` 与计数增量。
2. 如果是 `ALL 0`，优先核对是否在每圈原始角度 0/16383 附近重复出现。显示的 Raw 通常仍是最后有效角度，不是被丢弃的帧；需结合最后错误和必要的总线抓取判断。
3. 如果是 `ALL 1`，重点核对编码器是否在该次 CS 区间内驱动 DO、片选和连接是否可靠；仅凭全一还不能断言一定断线。
4. 有示波器时在编码器端测 VDD 对本地 GND，以及 CS/SCK/DO；核对功率输出后供电、地电位和信号是否异常。LCD 上的 VREF 慢速滤波正常不能排除编码器远端的瞬态供电问题。芯片附近的 0.1 μF 去耦参照 [MagnTek SSI 参考电路第 24 页](https://www.magntek.com.cn/upload/pdf/202407/MT6701_Rev.1.8.pdf#page=24)。
5. 比较相同工况下信号线与三相功率线分开、缩短连线、改善近邻地回流后的错误增量。若两路同时出错，共用供电和地更值得先检查；若集中于单轴，优先对应支路和接口。

## 验证

真实编码器驱动主机测试覆盖两类帧的区分、拒绝更新角度、保持错误分类计数、连续四帧导致不健康、有效帧恢复健康且保留历史计数；ENC2 五次失败停止、显式重试、SPI2 Flash/存储互斥继续通过。控制、UI/存储/LCD、USB 回归通过。时钟一致性、最终 ELF 启动顺序及 ELF/BIN 一致性检查通过。

Debug：Flash **131012 / 131072 B**，余 **60 B**；RAM **21616 B**。Release：Flash **130236 B**，余 **836 B**；RAM **21520 B**。保留已有 RWX LOAD 链接警告；尚未烧录或验证此次错误的实际电气根因。R39 时钟设置见 [Encoder_SPI_slow_clock.md](Encoder_SPI_slow_clock.md)。
