# UI-R43-ZEROLOG：区分零点附近全零与异常读零

本版增加 ENC1/ENC2 共用的全零事件记录，帮助判断 `ALL 0` 是在原始零点附近发生，还是从远离零点的位置突然读成全零。保留 R42 的 APB=170 MHz、编码器约 664 kHz、ENC2 按启用情况重连和恢复不自启；本轮无需修改 CubeMX。控制增益、主从算法、HSO 和判帧保护不变。

2026-10-23 用户后续实测：M2 磁铁对准后 Follow 中 E2 LOST 明显改善，单机各约 20 min 基本正常，仍有低概率 E1 LOST。完整读数、E1/E2 标注歧义及暂不改代码的决定见 [实板观察记录](Encoder_follow_field_log_2026-10-23.md)。

## 能判断什么

MT6701 的 24 位 SSI 帧包含 14 位角度、4 位状态和 6 位 CRC。**原始角度为 0 不等于整帧全零**：例如角度为零且按压状态置位的合法帧仍会接受。角度、状态和 CRC 全为零的帧既可能是真实零码，也可能是 DO/MISO 保持低电平，单凭这 24 位无法唯一判断。

因此本轮只增加证据，不直接把零点附近的全零帧当成有效反馈。没有放宽 CRC、磁场、3 周期样本年龄或五次连续失败保护，也不发布被拒绝帧中的零角度。真实零码停留多个采样周期仍可能触发原有掉线判定，这项歧义没有通过本轮诊断消除。

两路使用同一套解码和事件记录，与电机型号、极对数或主从角色无关。M2 被动手转只表示 M2 不输出 PWM；M1 跟随运行时整板仍有开关电流，不能据此排除共用供电/地或线束上的耦合。若两桥输出均关闭仍发生错误，则须同时排查通信时序、电源、连接与软件判帧，不能直接认定为相线 PWM 干扰。

## Status 新增行

| 行名 | 含义 |
| --- | --- |
| E1/E2 Zero | 最近一次全零事件的前帧位置类别，以及该事件中的全零帧次数，例如 `NEAR 5` |
| E1/E2 ZPre | 第一次全零前的最后有效原始角度，0～16383；没有可用前样本时为 `--` |
| E1/E2 ZPost | 事件开始后的第一个有效原始角度；尚未恢复有效帧时为 `--` |
| E1/E2 ZTime | 从第一次全零到第一次后续有效帧的毫秒数；等待恢复时持续增加，恢复后保留 |

标签仍随查看的物理轴切换，M2 为主机时仍读取 E2。`ZPre/ZPost` 是芯片原始码，不是对齐后的机械角度，也不是 rad。`ZTime` 使用 HAL 毫秒时基，0 表示同一毫秒 tick 内发生，不能证明持续时间为零；无符号差值处理一次 tick 回绕。

`Zero` 类别：

- **NEAR**：前样本仍新鲜，且原始码为 0～128 或 16256～16383，即绝对零点两侧约 2.81°。只是“发生在零点附近”，不证明全零帧真实有效。
- **FAR**：前样本仍新鲜，但在上述零点邻域之外。结合短 `ZTime` 和相近的前后有效角度，更支持读取毛刺；这不是依据电机最大速度作出的物理不可能判定。
- **GAP**：前样本年龄大于 3 周期、超过 5 ms 墙钟有效期，或启动/重试后尚无可用新样本。此时不依据前帧位置作连续性结论。
- **--**：复位以来还没有记录全零事件。

记录在第一次全零时冻结前角度和前帧有效性；中途 CRC/磁场错误不会被当作恢复角度，也不会覆盖事件起点。每次全零增加次数，最大 65535；该计数不是所有失败帧总数，也不保证中间没有其他错误。第一次后续有效帧记录 `ZPost` 和结束时刻，此后保持；下一次全零开始新事件并替换记录。它是最近事件，不是独立锁存的最初停机事件。

## 如何解释

| 观测序列 | 解释 |
| --- | --- |
| ZPre=16383，期间全零，ZPost=1，时间很短 | 与正常跨越绝对零点相符；单帧内容仍不能排除低电平干扰 |
| ZPre=7000，期间全零，ZPost=7002，时间很短 | 真实角度前后几乎不变且远离零点，更像通信中短暂读成零 |
| NEAR，ZPost 一直 `--`，ZTime 持续增加 | 可能停在真实零码，也可能信号卡低，软件不能唯一鉴别 |
| GAP 或长时间后才有 ZPost | 不应用相邻角度的小位移假设推断起因；失联期间轴可能已经转动 |

下次故障先选择 Status 的对应 Axis，记录四项以及 Last、Age。如果当前主机是 M2，应读取 E2。建议另做“两桥功率输出均关闭、手转经过一整圈”的对照，以观察是否每次都在绝对零码附近出现。

## 实现和验证

事件记录在各自发布路径中完成，控制 ISR 不增加格式化或日志输出。M1 诊断汇总改用统一结构，GetDiagnostics 在短临界区快照；两路不混用前角度或事件。UI 使用应用长期持有的标签和值，不改 KK_UI 核心、刷新、字体或页面路由。新增文字使用现有 ASCII 字模，真实字体下的行宽检查通过。

主机测试覆盖两路无历史、零点两侧、远离零点、持续全零、CRC 错误不充当恢复帧、旧样本/墙钟过期、事件替换、有效 raw=0、毫秒回绕和持续时间。原编码器掉线、重连、SPI2/Flash、存储、控制保护、UI/LCD、USB 回归继续执行。

为容纳诊断，RCC 基础 HAL 加入既有 LTO，保留调试符号、强 HAL_Init/MSP 和原启动时序；没有修改 RCC HAL 源码，也未删除保护或其他功能。全部主机回归、Debug/Release 构建、强 IRQ/MSP、启动顺序、ELF/BIN 一致性及 `.ioc` 时钟检查通过。

Debug：Flash **130396 / 131072 B**，余 **676 B**；RAM **21840 B**。Release：Flash **129612 B**，余 **1460 B**；RAM **21744 B**。保留已有 RWX LOAD 链接警告。最终 ELF、BIN、MAP 已更新。

当前固件 **UI-R43-ZEROLOG**，文件为 `build/Release/FOC_two.bin` 或同目录 ELF。R43 实现时仅完成软件验证，后续用户实板反馈见上方记录；本版提供定位信息，没有确认电气根因或宣称全零歧义已经解决。
