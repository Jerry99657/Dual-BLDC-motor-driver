# UI-R41-ENCDMA：E1/E2 诊断与 M1 DMA 超时恢复

本页保留 R41 记录。当前 R42 对启用的 ENC2 增加故障停机后的低频重连，并恢复 APB1/APB2=170 MHz、编码器约 664 kHz；当前固件及规则见 [Encoder_reconnect_clock_restore.md](Encoder_reconnect_clock_restore.md)。下文“五次失败后必须显式重试”和 332 kHz 为 R41 历史行为。

本轮用户已确认：M2 为手转主机，M1 为从机；错误来自 ENCODER2，Frame 固定在 6，Age=65535/65535，Last=ALL 0。这符合 ENC2 连续失败后停止探测的现有策略。Frame 为累计次数，停止条件为连续 5 次，两者不矛盾；Age 可在持续停更后饱和，不能据此认定 SPI 单次传输了 65535 个周期。

## 物理编号清晰显示

Status 中随 Axis 切换的编码器行改为 E1/E2 前缀：State、CRC、Field、Track、SPI、Frame、Age、Last、Raw、Err。例如查看 M2 时显示 **E2 Frame**、**E2 Age**、**E2 Last**。

编号跟随物理轴，与主从角色无关：M2 为主机时仍叫 E2。两项固定的第二编码器摘要改为 **E2 Probe**（健康/停止状态及最后有效 Raw）、**E2 Total**（累计错误），不跟随 Axis。停止记录的 Stop Age/Stop Err 也带来源，例如 `E2 5`、`E2 6`，即使当时 Run 正在查看 M1 从机，仍按最先失联的实际编码器取值。

UI 继续沿用应用层长期持有的标签和数值缓冲；只更新标签中的轴号。未修改 KK_UI 核心、刷新所有权、字体或页面布局。ASCII 字符沿用现有字模，实际字体下的诊断行宽度检查通过。

## M1 采样恢复

以前 M1 缺少在途 DMA 的超时清理：若完成回调不再到来，transfer_active 会阻止所有后续提交。本版增加：

1. 10 kHz 调度发现 DMA 持续超过 3 个未完成检查，即第 4 个检查时，记录 **DMA TMO**。正常调度约对应 0.4 ms；该时间从提交算起，不是样本年龄的 UI 值。
2. 主循环另外检查启动 tick 差值大于 1，覆盖 ADC 调度停下时的情况；毫秒粒度使实际检测时间约为 1～2 ms 加主循环延迟，使用无符号差值处理 tick 回绕。
3. 超时、HAL 启动失败或 SPI/DMA 错误后，将当前样本标为不健康，保持缓冲区所有权，暂停新提交。超时计入 **E1 SPI**，最近原因显示 **E1 Last=DMA TMO**；CRC/Frame 错误仍分别统计。
4. `MT6701_MainService()` 在主循环完成 HAL Abort、两个 DMA 通道清理、释放片选、SPI1 外设复位及重新初始化。控制中断只检测和标记，不执行这些可能阻塞的操作。SPI1 初始化失败时保留恢复状态，后续主循环再尝试，期间不提交新 DMA。
5. 清理期间的迟到完成/错误回调被忽略；完成回调发布数据期间另有状态保护，ADC 抢占不会提前复用缓冲或误触发在途超时。
6. 重新初始化成功后，下一 ADC 节拍恢复采样；只有新有效帧才能重新恢复健康。历史错误、最后原因和最大年龄保留，现有控制层仍负责掉线停机，采样恢复不自动使能功率输出。

显式 StopContinuous 会取消恢复及后续采样；重新 StartContinuous 后才恢复采样。SPI1 复位不涉及 SPI2/Flash、LCD、定时器或 ADC 配置。

## ENC2 策略继续保留

本轮未改变 ENC2 的五次连续失败停止、SPI2/Flash 互斥、显式 Retry/Align 或复位规则。M2 为被动手转主轴时，停止联动后对 M2 执行现有 Align 请求只重试编码器，不给主轴通电对齐；仍须满足停止条件。修好接线后仅等待，不会让已经停止探测的 ENC2 自动恢复。

全零帧仍存在真实零角度与异常低电平的歧义，详见 [R40 诊断记录](Encoder_constant_frame_diagnostics.md)。本版不会把持续全零直接当成健康反馈，也未确认这次 ENC2 的实际电气根因。通信时钟继续约 332 kHz，控制参数及主从算法保留；本轮无需重新生成 CubeMX。

## Flash 与验证

为容纳恢复逻辑，共享了 13 处既有 16 字节计数文本的格式化调用，并将 DMA、FDCAN、I²C、RCCEx、PWREx HAL 加入已有 LTO。未修改这些 HAL 的源码，未删除外设或保护功能，10 kHz HSO 处理及控制算法源码保持原样。

- 电机主机回归通过：包含新的 M1 DMA 挂起、ADC 停止、tick 回绕、HAL 启动/Abort/初始化失败、清理期间抢占与迟到回调、同步早完成、显式停采样与重启。
- 原有控制/保护、ENC2 五次失败、SPI2 Flash/存储互斥及恢复继续通过。
- UI 验证 M2 主机/M1 从机、查看轴切换、E1/E2 的标签与数据对应、停止来源保持、最长年龄字符串及行宽；UI/存储/LCD、USB 回归通过。
- Debug/Release 构建、最终强中断入口、HAL_Init/MSP 启动顺序及 ELF/BIN 一致性检查通过。

Debug：Flash **130980 / 131072 B**，余 **92 B**；RAM **21712 B**。Release：Flash **130196 B**，余 **876 B**；RAM **21624 B**。保留既有 RWX LOAD 链接警告。尚未烧录或进行本轮实板故障注入，主机测试不能代替实际电气波形及双轴中断耗时的测量。

烧录当前 `build/Release/FOC_two.bin` 或对应 ELF，确认 About → FW=**UI-R41-ENCDMA**。E1/E2 表示物理编码器；继续定位当前主机故障时读取 **E2** 诊断。
