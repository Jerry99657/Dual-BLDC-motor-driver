# R110：统一编码器速度估计

固件标识 `UI-R110-ENC`，Native 配置回执版本 110。协议布局、存储版本和所有已保存的电机参数不变，上位机继续兼容既有协议。

## 实现范围

新增用户模块 `mycode/encoder_estimator.c/.h`。M1 的 AngleSource 适配器与 M2 控制器各自持有一个 `EncoderEstimator`，共用新样本准入、单圈角差展开、多圈机械位置累加、四点差分速度、对齐复位和失联重同步逻辑。此前 R104 只共享四点差分算式，外围状态仍各写一份；这次移除两处重复跟踪代码及旧 `MotorMath_WindowVelocity` 接口。

- 保留 1 kHz 外环、填满后的 4 ms 差分窗口和机械 rad/s 单位。正常有效样本的数值计算顺序与原算法一致；没有新增 PLL、预测、滤波层或延迟。
- 方向仍取每轴独立参数，输入仍为驱动已经转换过的角度。M1 原始 SSI 计数与 `Angle` 方向相反的 R106 修正保留，不重新反转辨识结果；机械速度不乘极对数。
- 采样计数不变时不推进公共位置及差分窗口。计数跨 `UINT32_MAX` 继续按新样本处理。健康状态来自现有 MT6701 解码／时效判定，不改变全零帧、CRC、磁场或 DMA 保护。
- 失联时公共速度和窗口立即清零，保留已知多圈位置；恢复后的首个新帧只重新同步，不把未知位移除以 1 ms 形成速度尖峰。恢复通信不会自动启动电机。
- 对齐将机械位置、速度和窗口归零，并记录同一份对齐样本的计数。M2 运行失联后仍需手动对齐，随后填满四个有效差分样本才能启动。

M1 的速度低通仍在编码器／HSO 反馈选择之后，每个外环周期执行；M2 的低通仍只处理新的差分结果，在失联／重同步时归零。这些既有控制器行为和各型号 `Tf` 保留，没有调整 PID、主从跟随估计器、速度前馈或轨迹调校。因此这次是等效整理，不宣称改善实板的响应、噪声或跟随精度。

CubeMX `.ioc`、生成初始化及 IRQ、ST HAL／LL／CMSIS、USB 中间件和 KK_UI／KK_OLED 核心均保持本轮 R109 基线。CMake 只加入用户估算器源文件，并沿用编码器路径的 `-Os;-flto`；官方编译选项不变。现有构建检查继续拒绝不受支持的控制频率，每次正常构建执行 CubeMX 检查。

## 回归与资源

- 公共估算器：320000 点对照原算法逐点相等，含正反转、多圈、4 Hz 往复、低速计数量化、不同调用步长；另测重复帧、计数溢出、冷启动、对齐、失联恢复、两个实例隔离。
- 真实 M1 适配器及真实 SSI 驱动：方向、对齐、跨零、getter 无副作用、恢复无虚假位移，以及预设／辨识／Custom 方向回归。
- 真实 M2 控制器：16000 帧包含原低通的逐点对照，重复帧、故障停机、恢复首帧、稳定等待、手动对齐和显式重新启动。
- 完整电机主机回归：采样、保护、辨识、双机／主从模型、HSO、六步换向、协议、USB／USART 遥测与格式切换。
- UI／设置服务、HTML 控制台／真实浏览器串口流程通过。43 项 CubeMX 配置变更及 DMA／KEY1 映射回归通过；两个实际 ARM 镜像的启动、MSP、保护路径和 ELF／BIN 一致性检查通过。

本轮未烧录开发板。实板建议复核两轴正反转、跨圈、低速手转、主从往复和编码器断连后的手动恢复，同时记录 Ctrl Max／HSO Time；主机模型不能证明实板执行时间或抖动水平。
