# 双电机控制台 R102（单文件 HTML）

`index.html` 是完整的离线上位机。界面、Web Serial 通信、协议解析、曲线、CSV 记录／回放和配置查询都内嵌在文件中，无需 Python、安装依赖或运行后台。

## 界面导航

默认使用浅色界面，顶部可切换深色，选择保存在当前浏览器。字体已内嵌，离线打开也可完整显示。桌面左侧、窄屏底部的导航可跳转到监控、模式与驱动、参数设置、辨识与诊断、记录与回放；全部功能仍在同一页面。

全局 Stop 固定在顶部，滚动页面时仍可操作。曲线右侧上方为板端状态，下方为运行控制；桌面端滚动查看曲线及多个画布时，运行控制保持可见，可以同时发送目标。窄屏时两者顺序排列在曲线下方。顶部母线电压和双轴反馈速度来自最近收到的对应通道，没有数据时显示 `--`。曲线说明可展开查看，原有通道拖入、独立画布、采样缓冲条和快捷键均保留。

当前配置回执测试帧为 R115，读取的是现有 C 协议回归生成的真实二进制。上位机界面版本仍为 R102。`build/console-r87/`、`build/console-r88/` 和 `build/telemetry-r86/` 为沿用的测试目录名，不表示当前固件版本。JustFloat 不带固件版本字段；离线演示也只是模拟曲线，不与开发板通信。

R104 的辨识区域新增“应用保存的测量值”“恢复该轴预设电参”和“读取已应用参数”。保存与应用分开，两轴需停止，结果绑定电机型号；应用后重新对齐。每轴保留一份应用记录，保护阈值继续取型号预设。流程、单位、兼容迁移和当前资源占用见 [R104 参数应用说明](../docs/Control_params_R104.md)。

## 界面动效

按钮提供悬停、键盘聚焦和按下反馈；导航选中块平滑移动；画布说明和高级原始命令区展开／收起时有过渡；画布与通道增减提供进入、退出和位置调整效果。异步操作按实际处理状态显示忙碌反馈，成功和失败分别给出提示；命令反馈表示板端受理，不代替实际电机状态或 Flash 保存结果。

按钮增加独立亮边扫过，面板顶部标记、通道和状态行提供悬停／聚焦反馈。电流环、LED 使用方形开关；画布工具、缩放轴、时间轴、列数及设置电机轴使用分段选择，支持方向键、Home／End。它们仍通过原有控件更新状态，保留禁用条件，编辑不会自动发送指令。

CSV 载入和诊断查询显示 24 格进度：CSV 按实际读取字节数，诊断按板端返回的总行数和已收到行数计算；总量未知时显示等待状态，处理成功才显示 100%。失败或取消保留部分进度。CSV 载入期间点击“返回实时”、进入离线演示或连接串口会取消旧载入；重新选择 CSV 也会替换尚未完成的载入，避免旧任务覆盖新数据。同一个文件可以再次选择。

深浅主题通过圆形展开切换；正在接收数据或显示历史曲线时，只对页面背景做过渡，曲线与数值继续直接刷新。页面操作和 Stop 均不等待动画结束，减少画布也会立即更新实际绘图数量。系统开启“减少动态效果”时，当前动画立即结束，之后直接显示最终状态。串口授权和文件选择沿用系统原生界面。

“参数设置”底部的“页面动效”可选择完整／简洁，立即生效并只保存到当前浏览器，不写入板端。简洁模式省略首屏展开和主题揭幕，保留按钮、导航、开关、画布增减及确认框的操作反馈；系统“减少动态效果”始终优先，进度和实际数值照常更新。此偏好不会恢复或自动添加画布通道。

页面内的操作确认使用统一样式的原生对话框，默认聚焦取消；支持 Esc、点击遮罩取消及 Tab／Shift+Tab 循环焦点。弹窗期间全局 Stop 保持在原来的屏幕位置，可以立即停止并取消待确认操作，不等待退出动画。取消不发送操作指令、不显示成功提示；断线、板端重启或停止使旧确认失效。真实采样和绘图在等待确认期间继续进行。

未连接、正在连接、配置读取、等待遥测、未选择通道及历史回放分别提供对应提示；断开后保留的板端状态明确标注为最后接收值。空状态使用静态斜线纹，不填充模拟读数。开关开启态和 24 格进度使用黄色填充；触屏上的通道移除按钮与三个缓冲条手柄具有至少 44×44 像素的独立点击区域，手柄可见方块尺寸保持不变。

`python -X utf8 tests/pc_tool/test_components_browser.py` 验证确认框的取消／受理、焦点、即时 Stop、连接变化与重启使旧确认失效、连续开关和动画回收与采样并行、空状态、配色、动效偏好、系统减少动效优先级，以及触屏手柄的独立命中和实际触摸伸缩。动画完成或取消后先解除效果与元素的关联，再回收引用；此路径通过了本机 Edge 156.0.4314.42 的崩溃复现用例。测试使用模拟板端，不发送真实硬件指令。

## 使用

1. 板子使用本项目 `UI-R115-POS` 固件；构建产物位于 `build/Debug/`、`build/Release/`。R101～R103 也兼容原有功能，参数应用新增操作要求 R104；R88～R100 兼容完整设置／诊断，R87 仅兼容原有优先控制／读回功能。R102 的 Diagnostics 新增全局停止来源、时间／启动阶段及触发／实时按键状态，R103 修正 KEY1 冷启动电平检查过早的问题。
2. 用桌面 Chrome／Edge 打开 `pc_tool/index.html`。也可以把这一个文件复制到其他位置打开。
3. 点击“选择串口并连接”，在浏览器对话框中选择 USB CDC 或 USB 转 USART 的串口。USART1 保持 **115200、8N1**。
4. 工具首先发送普通文本 `Format:Native`，然后发送带编号的 `Get` 并等待配置回执确认。R101 上电默认 JustFloat，USB／USART 同步切换；连接不会自动运行电机，也不会用网页残留值覆盖板端设置。
5. 按工作模式、电机与驱动、Run 面板操作。切模式／型号／驱动沿用板端原有停机、轴使能、编码器及保护条件。

浏览器会要求串口授权；不支持 Web Serial 时页面会提示更换浏览器。`start.ps1` 仅为打开 HTML 的可选快捷方式。板子的 USB CDC 驱动或 USB 转串口驱动仍由操作系统提供。

“离线演示”保留模拟曲线预览，不打开串口或控制电机；`start.ps1 -Demo` 直接进入该模式。模拟记录使用 epoch -1，与实板连接分段区分。

## R101 发送格式

上电／复位为标准 JustFloat，USB CDC 与 USART1 共用格式。`Format:Native`／`Format:JustFloat` 切换两路输出，板上 Settings → System → `TX Format` 也可按 OK 切换；只保存在 RAM，不写 Flash。HTML 顶部提供发送格式选择；Native 保留完整控制／设置／诊断／CSV，JustFloat 用于 VOFA+ 波形接收，HTML 此时提示切回 Native 使用完整控制台，全局 Stop 仍可发送。

若从板上切到 JustFloat，网页识别连续标准帧并暂停 Native 查询，不自动改回格式。点击切换 Native 或重新连接后，先切格式再 Get 确认。JustFloat 不混入状态包或回执，默认 Auto 为固定 12 通道双轴布局；专用 HSO／Six 曲线可用 `Stream:HSO`／`Stream:Six` 选择。通道表、无效值、接口边界及实测见 [R101 协议说明](../docs/Telemetry_JustFloat_R101.md)。

Debug／Release Flash 均为 **130252 B，余 820 B**（较 R100 增加 524 B）；RAM 总分配 **29456 B**（增加 32 B）。无需调整 CubeMX；需要烧录本版固件才能使用新增切换。未修改 ST 官方库／生成配置或编译选项。`python -X utf8 tests/pc_tool/test_format_browser.py` 验证真实浏览器 Native-first 握手、手动／板上切换、查询取消、Stop 和恢复；没有打开真实串口或实际 VOFA+。

## 工作模式、电机与 Run 联动

三个面板根据所选工作模式更新，删除当前模式不适用的下拉选项。选择只预览界面；点击应用并收到板端回执后才生效。

| 工作模式 | 电机型号设置 | 驱动 | Run |
| --- | --- | --- | --- |
| 单 M1 | M1：2804／4015，六步下可选 ESC | 编码器 FOC／HSO／六步 | FOC：Speed／Angle／Torque；HSO：Speed；六步：Speed／Throttle；ESC：Throttle |
| 单 M2 | M2：2804／4015 | 编码器 FOC | 仅 M2，Speed／Angle／Torque |
| 双机独立 | 分别设置 M1／M2 | 编码器 FOC | 选择 M1／M2，Speed／Angle／Torque |
| 双机同步速度 | 分别设置 M1／M2 | 编码器 FOC | 仅 Speed，向任一轴发送即控制双机 |
| 双机同步位置 | 分别设置 M1／M2 | 编码器 FOC | 仅 Angle，向任一轴发送即控制双机 |
| M1 主机 → M2 从机 | 分别设置 M1／M2 | 编码器 FOC | 仅显示 M2 从机，使用 Follow 启动 |
| M2 主机 → M1 从机 | 分别设置 M1／M2 | 编码器 FOC | 仅显示 M1 从机，使用 Follow 启动 |

- 先应用工作模式，再应用需要修改的驱动／型号，最后发送运行目标。未应用的选择有明确提示，相关运行按钮暂停使用；驱动切换成功不会自动提交尚未应用的型号草稿。
- 普通模式中，切换电机设置轴与 Run 轴会相互联动，并读入对应轴的型号。主从模式始终保持 Run 为从机；仍可单独选择主机设置型号。
- 手动切换 Run 轴／控制方式会把目标输入归零，避免沿用另一轴／另一单位的目标；归零只修改输入框，不发送命令。
- 工作模式／型号／驱动被拒绝时，继续显示板端真实读回及未应用提示。点击“读取全部设置”可重新填入实际值；普通 ACK 保留未发送的草稿。
- Torque 输入单位随该轴电流环偏好显示 A／V。全局 Stop 始终保留，双机同步／主从的停止按钮明确标为“停止双机”。原始命令输入收进“高级原始命令”，仍可展开使用。

工作模式联动沿用 R100 的板端接口；本次 R101 格式切换需要更新固件，资源占用见上文。

验证：`node tests/pc_tool/test_console.js` 覆盖七种模式、实际 C 帧解析／回执、命令路由、草稿与拒绝路径；`python tests/pc_tool/test_wire.py` 覆盖传输。另有 `python -X utf8 tests/pc_tool/test_linkage_browser.py`，使用 Playwright 和本机 Edge 检查真实下拉框、读回、主从与 1440／768／390 px 布局；该依赖仅用于开发测试，HTML 使用时无需安装。测试使用模拟板端，未打开真实串口。

## 多画布、同轴对比与通道拖入

- **一个画布就是一套 XY 轴**，数量可选 **1～6**；通道数量、名称和单位都不会再增加轴组。每个画布共用时间 X 轴和数值 Y 轴，多条曲线直接叠加。不同单位只在通道标签／游标／数值中注明，不做换算或归一化。
- 点击增加／减少调整轴组数量。新增画布默认留空并显示一套空坐标轴；减少时隐藏后面的画布，在本页重新增加可恢复其通道与视图。支持单列／双列，窄屏自动改成单列。
- 将上方通道拖进任意画布即可添加；同一通道可重复放到多个画布，重复拖入同一画布会去重。画布内的通道标签也能拖到另一画布，原绑定继续保留；点击标签旁的 × 只移除该画布的绑定。
- 手机或不方便拖动时，先选“当前画布”，再勾选上方通道。点击／聚焦画布及其工具也会更新当前画布，蓝色边框标明当前对象。勾选框只控制当前画布。
- 自由组合示例：画布 1 放 `m1.target_speed` 和 `m1.feedback_speed` 比较跟随；画布 2 放 `m1.iq` 与 `vbus` 观察电流与母线的同步变化。也可把速度、位置、电流全放进画布 1，始终只有一套 XY 轴。
- “全部加入当前画布”将当前可用通道叠加到所选画布，保留其他画布的绑定。取消原有按单位分区／固定分配入口；新增曲线或移除曲线后重新适配该画布的 Y 量程，避免不同数值范围的曲线落在视野外。重复添加已有通道不改变视图。
- 每个画布独立保留时间窗口、实时偏移、X／Y 范围、暂停快照和游标。单一单位直接显示在轴标题；混合单位的 Y 标题显示“数值 · 单位见通道”。数值差别较大时，小幅曲线会被共用量程压缩，可自行放入另一画布观察。
- CSV 滑条作用于当前画布，旁边标明其编号；顶部“暂停绘图”暂停全部可见画布，各卡片的“暂停此图／继续此图”只作用于对应画布。“跟随最新”恢复该画布右端对齐，其余暂停画布保持。平移或暂停不停止接收和记录。
- 初始化时所有画布均为空，不会自动添加收到的通道；首次连接、离线演示或 CSV 载入也由用户自行勾选、拖入，或点击“全部加入当前画布”。采集组切换／板端重启后清除旧数据和快照，保留手动分配的通道。尚无当前数据的通道会灰显“等待采样”，不会沿用旧曲线或补零。

所有画布共用现有接收缓冲；实时显示不重复复制采样点，冻结时保存所选通道的只读快照。同一采样时刻、范围可复用的快照共享底层存储，各画布仍独立保留视图和暂停状态。数量及绑定只属于电脑端页面，不写入电机设置，也不增加板端遥测请求。仍是一个离线 HTML，刷新后从一个默认画布开始。

## 曲线交互

按用户提供的 2026-10-28 录屏修正实时视窗：拖拽／滚轮／框选不再隐式复制并冻结数据。默认横轴以最新点为 0，小于 1 秒的窗口显示 ms；“板端时间”可查看原始时间坐标。负偏移显示持续更新的延迟窗口，正偏移在最新点右侧留空；两者均随采样继续推进。只有主动暂停才保留固定快照。

已补齐录屏 4～7 秒的采样缓冲范围条：红色左端拖动改变窗口起点、保持右端；紫色右端拖动改变终点、保持左端；绿色中点或选区整体拖动平移，保持窗口宽度。接近的左右端手柄使用分开的点击区域，中点位于上方；鼠标、触摸 Pointer Events 和键盘方向键均可操作，Shift＋方向键放大步幅。操作期间维持实时刷新，主动暂停后则操作该画布的固定快照。悬停可查看起止相对时间、可视／缓存点数和真实 X 轴每格时间。

“缓存时长”允许 **0.001～86400 秒**及小数，例如 0.2、2.5、100；回车、失焦或点击“应用缓存”同时设置保留时长和 X 轴宽度，并将右端对齐最新点。例如设置 100 秒后，按采样时间保留最近 100 秒的原始点，不再固定为每通道 2200 点。应用保留当前 Y 量程；已暂停时对齐暂停快照的最新点，仍保持暂停。图上方显示当前视窗宽度、实际缓存跨度、设定保留时长和右侧留白／滞后。

每个画布独立设置缓存时长。拖拽、滚轮、缓冲条和“全部缓存”只改当前视图，不改变数据保留时长；例如缓存仍为 100 秒时，可放大观察其中 5 秒。点击“应用缓存”恢复到相对最新点的 `-100～0 s`；复位／Home 还会恢复自动 Y 和实时跟随。空值、非有限数和超范围输入显示错误，保留当前视图和上次有效时长；编辑不会中断接收或发送电机命令。

所有通道共享一份实时存储，按已创建画布中最长的缓存时长保留，隐藏画布的设置也保留。每个画布只读取自己的时间范围：同一通道可在画布 1 查看最近 100 秒、在画布 2 查看最近 10 秒，不重复存储实时采样。“全部缓存”按该画布范围内实际已有的数据设置 X 量程。缩短最长时长会立即裁剪旧点；增大时长后继续积累，不能补回已经丢弃的数据。暂停快照独立保留，不被后续实时采样覆盖；缩短该画布时长时，也会裁剪它的暂停快照。

采样使用 Float64 循环缓冲，保留原始时间和值，不按点数降采样。实时缓存仍保留 200 万点上限；实时数组、暂停快照和峰谷索引另共用 **128 MiB 的实际缓冲分配预算**，包括数组预留容量和隐藏画布保留的快照。达到限制时淘汰最旧的实时点，并在图上方明确提示“已达内存上限，缓存不足设定时长”，同时显示实际跨度。已有暂停快照不会被覆盖；新增暂停若无法容纳，会显示错误并保留当前状态。“暂停全部”先统一检查，不会只暂停其中一部分。这是采样缓冲预算，不是整个浏览器进程的内存上限；CSV 记录仍遵循独立的记录限制。限制不改变串口接收或控制，完整长时间记录可继续保存到 CSV。

单位标题与数字刻度分行绘制，刻度宽度按实际字体测量。X 轴数字按可用宽度排列；窄屏、DPI 缩放和大偏置／小变化的科学计数刻度均有浏览器回归。

### 持续绘图与浏览器稳定性

实时数据的重绘合并到最高 30 帧／秒，状态栏计时器不再重复触发曲线重绘；接收、缓存和 CSV 记录仍按原始数据处理。密集曲线绘制时按物理像素保留首点、峰谷和末点，保持时间顺序及无效值断线；放大到稀疏区域时逐点绘制。每条 Canvas 路径最多 2048 个顶点，分段处保留连续性。此优化不减少缓存中的采样点，也不改变用户选择的缓存时长。

进一步完成的五项优化：

1. **复用显示节点**：数值卡片、板端状态行和顶部读数保留现有 DOM，仅在文字变化时更新。通道、启用轴等结构变化时才调整对应节点。
2. **按可视范围自动绘图**：离开视口的画布停止自动重绘，接收、缓存和记录继续；返回视口立即补画最新数据。隐藏标签页同样暂停自动绘图。手动修改视图和初始化仍可触发一次绘制。
3. **统一缓冲预算与共享快照**：实时数组、暂停快照、索引按实际分配字节计量；同一时刻的快照可共享只读存储。缩短其中一个画布的缓存不会裁剪另一个画布的历史，恢复实时后释放该画布的快照引用。
4. **分块峰谷索引**：以 16 点为一块维护最小值、最大值及断线计数，长窗口量程查询和密集绘图复用索引，避免每次从头扫描所有原始点。环形覆盖、缩容、暂停和 CSV 数据采用同样的查询路径。
5. **本地诊断与长时间验证**：页面底部“浏览器运行诊断”可查看采样帧率、自动刷新率、近期绘图 P95、实时／快照点数和缓冲分配；导出 JSON 包含浏览器版本、各画布设置、最近指标和错误，不包含原始采样数组，也不发送板端命令。指标最多保留 120 条，错误最多 100 条；每 10 秒在当前浏览器保存简要检查点，并在正常离开页面时标记。检查点不能单独判定是否发生浏览器崩溃。

`node tests/pc_tool/test_performance.js` 比较峰谷索引与逐点结果，覆盖环形覆盖、断线、同值位置、视图、快照共享、小预算拒绝和全部暂停的原子检查。20 万点测试中，完整范围峰谷查询无需逐点扫描，800 像素密集绘图的逐点访问为 11200 次，原始点仍完整保留。`python -X utf8 tests/pc_tool/test_performance_browser.py` 验证实际 DOM 复用、离屏接收／停止重绘／返回补画、独立快照时长和真正的诊断下载。

`python -X utf8 tests/pc_tool/test_stability_browser.py` 默认进行 **1800 秒真实计时**的 Edge 持续运行：200 Hz、6 通道、100 秒缓存、6 画布及 20 Hz Native 状态包，包含分片解析、暂停／恢复、隐藏／恢复、确认框与主题动效、Stop 路径、内存／DOM 和诊断导出。它使用本地模拟包，不打开串口；`FOC_SOAK_SECONDS` 可缩短为开发冒烟检查，报告会明确标记是否达到 30 分钟。输出默认位于系统临时目录 `foc-pc-soak`，可通过 `FOC_SOAK_OUT` 指定。实际完整验证结果见 [持续运行验证记录](PERFORMANCE_VALIDATION.md)。

`python -X utf8 tests/pc_tool/test_render_budget_browser.py` 检查峰谷、断线、原始点、绘图路径上限，并以 200 Hz、100 秒缓存、6 个画布持续运行 30 秒，检查重绘频率、内存与 DOM 稳定及 Stop 响应；使用模拟数据，不连接开发板。`STATUS_BREAKPOINT` 表示浏览器进程崩溃，不能仅凭错误码确定原因；降低绘图压力不等于已排除浏览器、扩展或显卡驱动问题。

HSO 只允许 Speed；ESC 通用六步只允许 Throttle，并显示电气 Hz。预设六步保留 Speed；双机均为有感。Torque 的单位依电流环设置为 A 或 V。保存的 Uq 不等于实时 Iq 目标。

工作模式、型号、反馈、Gear、Focus 通过现有板端配置入口修改真实 RAM 设置并请求保存。回执“已受理”与 W25Q64“已保存”是不同状态；保存可因 SPI2 占用而延后。读取全部设置可刷新最新保存阶段，板上操作后也应重新读取快照。

**第 4～6 批已接入**：Settings 编辑页可修改两轴电流环偏好、限速、位置速度和三种步长，以及 LED、跟随比例／偏移、IBUS 阈值。运动指令自动进入板端 Run 并同步目标；参数修改保持原页面。本地编辑框打开时拒绝远程设置。型号选择复用本地菜单清零逻辑。

新增参数辨识开始／停止／保存结果、所选 Settings 轴重新对齐、IBUS 清除、恢复默认、HSO 操作。诊断可按两轴读取板端八组 Status／About 信息行，不改变 LCD View。仅完整成功的检测结果允许保存，不自动替换型号参数；固化 PID／预设不新增编辑入口。

配置导入使用本版导出的 JSON 格式，先校验、显示差异并确认，再 Stop 并锁存全局暂停后顺序应用；遇拒绝／超时即中止，已应用项不自动撤回，可读取实际状态确认。导入不会启动电机，结束保持 GLOBAL STOP；需要时显式对齐，再手动运行。模式／型号切换仍需要停稳，按板端错误提示处理。

回执只表示受理或拒绝；点击读取刷新 Save 状态。普通保存合并约 2 秒，或显式请求保存；SPI2 占用时仍会延期，Saved 才表示已完成写入／校验。详细协议、范围和验证见 [R88 实施说明](../docs/PC_console_R88.md)。

## 通信与记录

USB CDC 与 USART 共用数据帧；同一端口请由一个程序独占。本工具一次等待一条普通命令的回执；Stop 可打断等待。板端 Stop 立即执行并清空待执行队列；Key1 全局停止及原有保护持续有效。断开通信本身不等于停机。

使用支持本地文件写入的浏览器时，记录可直接写入选择的 CSV；其他情况下采用最多 16 MiB 的内存记录，到达上限自动导出并停止。暂停绘图仍继续解析与记录。CSV 载入也按各画布缓存时长保留最后一段采集组／重启分段的数据，可在已有范围内平移和缩放；如需从文件重新取得更早的数据，先增大缓存时长再重新导入。回放期间阻止普通运动发送，全局 Stop 仍可用。

HSO 相对机械位置仍来自 HSO 电角度跨圈展开／极对数，不读取编码器；每次连续合格 CONTROL 重新建立零点，失锁／停机后无效。

`server.py`、`wire.py`、`requirements.txt` 保留作旧 Python 桥接和脚本／协议测试用途；本 HTML 不调用它们的 HTTP API，也不依赖 CDN。旧 R86 可接收原有遥测，完整控制与查询需 R87；配置握手未完成时禁止普通运动指令。

协议、Flash 实测与验证见 [R87 实施记录](../docs/PC_console_R87.md)。本次未连接真实串口、未烧录，已完成主机模型与构建验证；真实浏览器授权、长时间文件记录和 USB／USART 实板联调待验证。

接口依据：[Chrome Web Serial 官方说明](https://developer.chrome.com/docs/capabilities/serial)。
