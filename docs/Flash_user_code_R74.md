# R74：只优化用户代码的 Flash 占用

R75 在本页成果上继续优化用户协议解析与配置命令识别，当前 Flash 余量为 2800 B，详见 [R75 协议优化](Flash_protocol_R75.md)。下文保留 R74 的独立构建与验证记录。

2026-10-25，固件 **UI-R74-OPT**。本轮将应用层 `ui_app.c` 的文本格式化迁移到 `UiText_Format()`，保留全部菜单、诊断项目、数值格式、控制功能和调试符号。

## 实测结果

| 项目 | R73 | R74 | 变化 |
| --- | ---: | ---: | ---: |
| Debug Flash | 131064 B | 129000 B | 回收 2064 B |
| Release Flash | 131064 B | 129000 B | 回收 2064 B |
| Flash 余量 | 8 B | 2072 B | 增加 2064 B |
| RAM | 23104 B | 23080 B | 减少 24 B |

容量仍按真实的 Flash 131072 B、RAM 32768 B 计算。保持原编译优化策略和 Debug 的 `-g3`，没有扩大链接区域或删减功能。原 RWX LOAD 段链接警告保留。

## 修改范围

- 新增 `mycode/ui_text.c/.h`：应用显示专用、有容量限制、无堆分配的格式化函数。
- `mycode/ui_app.c`：原 `snprintf` 调用统一改用新函数，参数和格式字符串完全相同；About 版本更新为 UI-R74-OPT。
- `CMakeLists.txt`：加入新用户源文件，沿用现有 `-Os / LTO` 选项。
- 添加格式化对照测试，并扩展链接后检查。

`Drivers`、`Middlewares`、`ThirdParty`、KK_UI 核心以及 `Core/Src/stm32g4xx_it.c` 的 153 个文件与本轮修改前的 SHA256 全部一致。未修改 HAL 官方函数、ST HSO／定点数学库、中断分发、采样流程、控制增益、保护或协议。

需要更正此前体积分析的一点：MAP 中 `HAL_ADC_IRQHandler`、`HAL_TIM_IRQHandler` 的链接后大小包含 LTO 内联进去的用户回调，不能把整个符号大小都算作 HAL 库本身的开销，也不能直接当作可节省空间。

## 格式化范围

本项目实际显示只需要：

- 无填充的 `%s`、`%c`、`%%`。
- 32 位 `%d`、`%u`、`%X`，支持 `l` 参数长度、非负数字宽度／`*` 宽度、补零。
- 原应用仍先将物理量换算为定点整数，按原小数位和单位拼接，未改变数值舍入。

新函数是独立的应用 API，不覆盖全局 `snprintf` 或其他标准库符号，不替换库内部函数。它只实现当前显示需要的格式，浮点 `%f`、精度和其他标志不在契约内；未知转换返回 −1，并保持已输出内容终止。

容量为 0 时允许空缓冲区；其他容量预留终止符。返回值为未截断长度，长内容保持与当前 `snprintf` 用法相同的截断结果。编译器继续检查格式字符串和参数类型。

最终链接中 `snprintf`／`sniprintf`、`_printf_i`、`_svfprintf_r`／`_svfiprintf_r` 已退出固件。新 `UiText_Format` 主体为 420 B；2064 B 是最终链接净收益，包含相关支持代码、调用点和初始化数据的变化，不能简单用单个符号大小相减推算。
