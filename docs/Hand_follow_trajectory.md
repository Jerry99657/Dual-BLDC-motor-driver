# UI-R32-FOLLOW：主从追赶轨迹与超调调整

本页保留 R32～R34 的追赶轨迹公式与参数。当前 **UI-R36-SMOOTH** 的 4015 电流闭环另加入快速参考、慢速输入整形和末端捕获，见 [4015_smooth_follow.md](4015_smooth_follow.md)；R35 高速基线见 [4015_fast_follow.md](4015_fast_follow.md)。主轴继续关闭功率输出，普通 Position、Sync Position 的位置 P 仍为 6，无需修改 CubeMX。启动修复见 [Startup_error_handler.md](Startup_error_handler.md)。

## 控制关系

每次 OK / Follow 捕获两轴起点。仍按连续多圈机械位置、比例和偏置计算最终目标：

```text
最终目标 = 从轴起点 + offset + ratio × (主轴位置 - 主轴起点)
目标运动速度 = ratio × 主轴滤波后的实测速度
```

在 1 kHz 外环中，在线追赶参考发生器根据这两个量生成连续的 `p_ref / v_ref`。从轴控制改为：

```text
速度指令 = v_ref
         + P × (p_ref - 从轴实际位置)
         + damping × (v_ref - 从轴滤波后的实际速度)
```

指令先受从轴 Pos Speed / Speed Limit / 型号上限约束，再经过已有的速度给定斜坡和速度 PI；Curr Loop=Off 时输出 Uq，On 时输出 Iq，再由电流 PI 调节。从机不再直接用位置 P=6 追赶最终目标。速度阻尼使用已有滤波速度，不对跳变的位置目标求差分，也没有增加位置积分。

“规划参考 + 反馈修正”结构可参照 [WPILib 的轨迹与 PID 组合说明](https://docs.wpilib.org/en/stable/docs/software/advanced-controls/controllers/profiled-pidcontroller.html)；速度前馈与位置修正的串级关系可参照 [SimpleFOC 的实现说明](https://docs.simplefoc.com/motion_control_implementation)。本项目使用轻量 C 参考发生器，没有引入上述库，也不是完整的最短时间或限 jerk 轨迹算法。

## 追赶与提前制动

参考发生器使用最终目标与参考位置之间的偏差，先把主机速度换算到从机机械单位并限幅。以 `v²/(2a) + T×v` 计算带参考响应余量的停止距离，对比当前目标的停止位置，限制追赶速度。移动目标的速度包含在停止位置内，不能直接把 `sqrt(2a×偏差)` 加到主机速度上，否则高速追赶/反向时会过晚制动。

接近目标时使用线性追赶区，并对参考速度增加阻尼；固定目标、未触及限幅时，该区对应临界阻尼的二阶参考响应。参考速度变化再受加/减速度限制，参考位置按前后两次速度的梯形积分更新。每毫秒重新规划，主机改变方向不需要再次 Follow。

启动从当前从轴位置、速度开始；非零 Gear Offset 也逐步追赶。重复 Follow 不重新置零。Stop 或故障停止后，下一次 Follow 丢弃旧参考、重新建立起点。Run 的 Error / FOLLOW ERROR 始终比较从轴实际位置和**最终主从目标**，不会改成较小的轨迹跟踪误差而掩盖落后。

## 初始参数

R34 参数位于 `mycode/motor_params.c` 的 `follow_voltage / follow_current`，每次启用按从轴型号及实际应用的 Curr Loop 选择，尚未加入 Settings 的可编辑项：

| 参数 | 2804 Off/On、4015 Off | 4015 On | 用途 |
| --- | --- | --- | --- |
| accel | 40 rad/s² | 55 rad/s² | 参考加速度 |
| decel | 40 rad/s² | 100 rad/s² | 参考减速度与停止距离 |
| P | 2 s⁻¹ | 3 s⁻¹ | 轨迹位置误差修正 |
| damping | 2 | 0.6 | 相对参考速度的阻尼 |
| response | 16 s⁻¹ | 24 s⁻¹ | 参考发生器响应 |

`response` 控制参考发生器响应，不等于位置 P。原速度给定 100/150 rad/s² 斜坡、电压/电流限幅及保护门限保留；由于误差修正和实际电机动态，参考加减速度不等于实际轴加速度保证。

Settings 仍可调整从轴 Pos Speed、Speed Limit。运行中降低限速，最终速度指令立即按新上限钳位，内部参考速度从旧值按有限减速度降下来，实际轴也需要制动时间。提高限速不会重置轨迹。旧配置和保存格式不变。

## 电压模式模型比较（R34 保留 R32/R33 预设）

用真实 M1 / M2 控制代码、编码器解包/滤波和 1 kHz / 10 kHz 回调，驱动理想的一阶电压—速度模型；分别使用 5、20、100 ms 时间常数、两种型号和两个从轴方向。Curr Loop=Off。旧版比较使用修改前保存的 R31 协同代码，保留相同速度 PI、模型和输入。

启动后 0.1～0.2 s，主机转动 1 rad 后保持。结果范围如下，时间从启用跟随开始计：

| 指标 | R31：原始速度前馈 + P6 | R32：追赶轨迹 + 修正/阻尼 |
| --- | --- | --- |
| 2804 最大越界 | 0.042～0.069 rad | 0.009～0.010 rad |
| 4015 最大越界 | 0.105～0.193 rad | 0.021～0.024 rad |
| 2804 到达 90% | 0.373～0.411 s | 0.421～0.449 s |
| 4015 到达 90% | 0.442～0.463 s | 0.457～0.498 s |
| 2804 保持在 ±0.02 rad 内 | 0.781～0.983 s | 0.518～0.588 s |
| 4015 保持在 ±0.02 rad 内 | 1.206～1.481 s | 1.089～1.359 s |

另在 1.0～1.2 s 将主机从 +1 rad 转到 -1 rad 后保持。反向终点的最大越界：2804 由 0.221～0.531 rad 降为 0.013～0.016 rad；4015 由 0.340～0.654 rad 降为 0.030～0.038 rad。部分 4015 工况最终进入 ±0.02 rad 的时间更长，不能据此宣称所有工况都更快。

还覆盖了 3 rad 追赶（100 ms 模型，两种型号/两轴）、目标突变/反向、比例 -2 和非零偏置、运行中限速 8→2→5、连续参考的速度/加速度边界、停止/重启和原有故障路径。`tests/motor_host/run.py` 可复跑新算法；`control.exe follow-model` 单独输出跟随模型结果。

这些模型没有辨识真实惯量、摩擦、负载、饱和电压变化或热行为，电流环的实际动态也未在此建模。结果用于代码比较，不能保证板上超调百分比。高速主机突然停止/反转时仍可能越界：例如参考以 10 rad/s 运动，仅按 40 rad/s² 制动就需要 1.25 rad 距离，目标突然停止无法提前预知。

## 上板试验

1. 确认 About 固件版本；沿用当前有感驱动和 Curr Loop 设置，先保持从轴 Pos Speed=30，Gear Ratio=100、Offset=0。
2. 两轴放在相同机械方向，进入 Master M1 或 Master M2，等从轴对齐并静止，按 OK 启用。
3. 先慢转 30°～90°后保持，再试反向和较大角度。观察 Run 的最终位置 Error，以及 Status 的 Drive、Encoder 和 Ctrl Max。
4. 串口遥测中，M1 实际位置/速度为第 14/2 通道，M2 为第 20/18 通道，第 25 通道为最终主从误差；目标速度为第 1/19 通道。记录超调角度和往返次数，再决定调整从轴型号的阻尼、位置修正或轨迹加减速度。

编码器、ADC、电流/过载、联动停止和手动重新启动规则继续有效。此次不需要改 CubeMX，也没有烧录或运行实际电机。
