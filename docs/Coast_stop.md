# Run 停止改为滑行（UI-R26-COAST）

用户确认：4015 在 Run 页再次 OK / KEY2 停止时容易过流，把 Speed 改为 0 则正常。本次针对专用停止，不屏蔽或提高过流阈值。

## 原因与行为

旧 `stop_run()` 把模式改为 Torque、目标 Uq 清零，并关闭电流 PI。快速环仍运行，最终三相占空比都为约 50%。相电压差为零，但六个 MOSFET 仍同步开关；对于正在旋转的电机，这个零矢量形成动态制动电流。它不能代表桥臂已断开，是本次应先修复的明确软件问题。尚未通过板上波形证明它是这次过流的唯一来源。

制动与滑行的物理区别及回馈路径见 [TI 电机驱动系统设计，第 7.1 节](https://www.ti.com/lit/an/slvaf66/slvaf66.pdf)。

当前行为：

| 操作 | 处理 |
| --- | --- |
| Run 正在运行且目标未变，再按 OK | 立即撤下六路 M1 功率 PWM，滑行停止 |
| Run 运行中 KEY2、离开或切换模式 | 撤下输出；重新运行需再次明确确认 |
| 串口 `Stop` | 使用同一滑行停止接口 |
| 运行中确认 Speed=0 或发送 `Speed:0` | 保持原有闭环减速及 HSO 低速返回策略 |
| 后台存储、UI 更新、采样服务 | 不会自行恢复停止的输出 |
| 滑行尚未结束时再启动 | UI 提示 `Wait for stop`；源速度绝对值须 ≤1 rad/s 才接受重新接通 |

滑行不会主动抱死转子，停止时间取决于惯量、摩擦和负载。停止后先等轴基本停稳再启动。串口在滑行速度较高时发来的新运动指令不会自动排队启动，停稳后需重新发送。

## 实现

- `JerryFOC_stop()` 先关闭六路输出，再清空三模式目标、PI 积分与上次输出、开环/HSO 接管状态，并准备中性 PWM 比较值。保留采样故障和 HSO 失锁历史。UI 沿用原有停止时关闭 Curr Loop 的方式，下次确认运行按 Settings 重新应用；串口停止不擅自改变原电流模式设置。
- `MotorSampling_SetOutputEnabled(false)` 只清 TIM1 CC1/2/3 的 E/NE 六位，保留 CC4/OC4REF、MOE、计数器、同步 TIM8 和规则/注入 ADC。采样硬件就绪与功率输出使能分开管理，Stop 后 Drive 可以仍为 READY。
- 再次启动须通过 `JerryFOC_startOutput()` 的采样、编码器、标定、失锁阻断和停稳检查；随后等待两个注入帧，让新比较值经过自然 PWM 更新后再接通，避免沿用旧占空比。等待期间再次 Stop 会取消请求。
- TIM1 的 PE8～PE13 增加下拉，保证禁用复用输出后的有效高门极驱动输入保持低电平；`Core/Src/tim.c` 与 `FOC_two.ioc` 同步。M2 仍不使能功率。
- 停机后继续更新相电流和速度显示。1 kHz 外环在停止状态不累积 PI，10 kHz 快速环不会重新施加电压。
- 串口 Speed/Angle/Torque/OpenLoop 在恢复输出前统一校验有限数值；错误字符串或 NaN 不会重新接通输出。
- 闲置 Run 页的导航不打断独立的启动对齐；明确串口 Stop 可取消正在进行的对齐，被取消的对齐不能被标为成功，需重新初始化/选择另一型号再对齐。

HSO 的正常接管/低速返回/失锁恢复策略不改；本次专用 Stop 与运行中 Speed=0 的处理明确区分。

## 保护与诊断

4015 的瞬时 2.5 A、过载基准 1.4 A / 超额平方电流预算 3 s 保持，2804 原门限保持。没有停止保护盲区：桥臂关闭后测得的剩余绕组电流若越界仍会触发并锁存保护。滑行也不等于所有回馈电流消失，母线及参考采样继续运行。

Status 新增 `Output`：`PWM` 表示输出启用，`COAST` 表示主动撤下输出，`OFF` 表示已请求输出但硬件尚未接通/故障撤下。Run Stop 的首因保留机制继续生效，额外识别 `OUTPUT OFF`。

建议板上复测：About→FW=`UI-R26-COAST`，Motor=4015；在当前 20 V、Speed 10 rad/s 下分别测试运行中 OK 和 KEY2。正常停止后 Output 应为 COAST，BusCnt/FrameCnt 继续增加，编码器/母线仍更新；等轴停稳后重新确认可启动。再确认 Speed=0 仍按原控制逻辑减速。若仍出现 M1 OVERCURRENT，保留 I Trip 和原始电流现场，再检查实测残余电流/母线，不以屏蔽保护作为验收。
