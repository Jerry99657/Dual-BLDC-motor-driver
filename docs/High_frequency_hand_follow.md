# 小范围高速往复主从跟随：算法调研与 R34 限制

日期：2026-10-22。调研基线固件为 UI-R34-FOLLOW；本文件记录基线代码分析和后续实现建议，调研阶段未修改控制代码或上板验证。

后续进展：UI-R35-TRACK 已完成参考、测速与外环优化，见 [4015_fast_follow.md](4015_fast_follow.md)。下文保留调研时的 R34 基线；惯量电流前馈仍需辨识后实现。

用户反馈：4015 从轴，Curr Loop=On、Pos Speed=120，比之前流畅、响应稍快，但超调增加，小角度快速往复仍跟不上。用户已确认目标为 **±10°、每秒完整往复 4 次、4015 空载**；实际转子惯量及电流到加速度增益仍未辨识。

## 代码中可确认的约束

- `mycode/motor_params.c`：4015 电流模式跟随参考加速/减速为 55/100 rad/s²，response=24 s⁻¹，位置修正 P=3，附加相对速度反馈系数 0.6。response 的单位不是 Hz。
- `mycode/motor_control.c::coordinate()`：主机位置先经过带停止距离包络、速度平滑和加减速限制的追赶参考，再作为从轴位置目标。速度前馈使用的是这条参考的速度。
- `MotorControl_PositionVelocity()` 输出经过位置速度上限，随后 M1、M2 各自还有 100/150 rad/s² 的速度给定斜坡。
- M1 的 `angle_src_encoder.c` 和 M2 的 `update_encoder2()` 使用约 4 ms 的位置差分测速窗口，后面另有 5 ms 一阶低通。4 ms 是差分跨度，不等于额外纯延迟 4 ms；需要结合频率看相位。
- 目前没有主机加速度到从轴 Iq 的惯量前馈。速度 PI 主要依靠跟随误差产生加速/制动电流。
- 两型号 current bandwidth 参数为 250 rad/s，约 40 Hz；这是按 R/L 设置 PI 的设计参数，不是实测闭环带宽。10 kHz 是电流控制执行频率，不能当作跟随带宽。
- 通用外环 PID 对积分状态做幅值限制，但没有针对“PI 与电流前馈之和”的饱和回算。M1 电流内环已有电压矢量限幅回算，不能把它描述成整个工程都没有抗积分饱和。

因此，“更平顺”“目标阶跃更快”“高速往复幅值与相位更准确”是不同指标。此前以追赶、到位为主的模型不能充分验证高速往复表现。

## 小角度也需要很高的加速度

机械角度按 `theta=A*sin(2*pi*f*t)` 变化时，A 用 rad，f 用 Hz：

```text
最大角速度 = A * 2*pi*f
最大角加速度 = A * (2*pi*f)^2
```

| 单侧幅度 | 每秒完整往复次数 | 最大速度 rad/s | 最大加速度 rad/s² |
| --- | --- | --- | --- |
| ±5° | 2 | 1.10 | 13.78 |
| ±5° | 5 | 2.74 | 86.13 |
| ±10° | 3 | 3.29 | 62.01 |
| **±10°** | **4（用户目标）** | **4.39** | **110.24** |
| ±10° | 5 | 5.48 | 172.26 |

表中按正弦机械角度、1:1 主从比计算，并非板上测量。用户目标的周期为 250 ms，峰值速度约 4.39 rad/s（41.9 rpm），峰值加速度约 110.24 rad/s²。它既超过跟随参考的 55/100，也超过后级速度给定的加速上限 100。因此将 Pos Speed 从当前 120 继续加大不会解除这些约束；只调整第一级参考，也仍可能在第二级被限幅。手动突然换向时，加速度需求还可能更大。

空载仍有转子自身惯量和摩擦。可用加速度还受实际惯量、Iq、电压和机械共振约束，不能直接把 110.24 作为新预设：跟踪修正还需要余量，前馈权重需要辨识。当前资料可确认软件约束冲突，尚不能保证现有限流下的实机响应。

## 参考生成层本身也可能放大往复幅值

仅按当前 `coordinate()` 公式和 4015 电流模式参数作 1 ms 数值复现：主机角度为正弦；速度由 4 ms 差分加 5 ms 低通得到；速度上限为 120；运行 12 秒、去掉前 2 秒，用正弦/余弦投影求参考角度基波幅值及相位。

| 主机输入 | 参考/主机基波幅值比 | 参考基波相位 | 参考相对主机角度误差 RMS |
| --- | --- | --- | --- |
| ±5°，1 Hz | 1.075 | −1.9° | 0.293° |
| ±5°，2 Hz | 1.186 | −11.0° | 0.986° |
| ±5°，3 Hz | 1.219 | −23.2° | 1.750° |
| ±5°，5 Hz | 0.913 | −56.0° | 3.188° |
| ±10°，5 Hz | 0.512 | −75.6° | 7.100° |

这里只复现参考生成层，不包含位置/速度/电流控制、PWM、电压饱和、转子惯量、编码器通信延迟，不代表实机幅值或相位。相位栏为周期信号的相位角，不是电机机械角度误差。非线性限幅还会产生谐波，幅值比只描述基波。

这个现象也可由局部线性化解释：忽略停止距离分支和所有限幅，令 response=R，测速传递函数为 Fv(s)，则近似有：

```text
reference_dot = reference_speed
reference_speed_dot = 2*R*(master_speed + R/2*(master_position-reference) - reference_speed)

reference(s)/master_position(s)
    = [R^2 + 2*R*s*Fv(s)] / [s^2 + 2*R*s + R^2]
```

即使分母是临界阻尼形式，整个跟随传递函数仍有前馈零点与测速相位，不能由“临界阻尼”推出往复无幅值放大。这为用户反馈提供了代码层面的可能原因，尚不能据此归因所有实物超调。

## 推荐：电子齿轮直接跟随＋速度前馈＋加速度电流前馈

针对手动主机、被动测角、从机有感电流控制，建议保留现有平滑追赶方式，另提供快速跟随策略。快速策略在执行器能力范围内直接使用主机映射后的机械位置；速度、加速度来自低延迟状态估计，不再把每一个新位置当成独立到位任务。

```text
主机连续角度/时间戳
  -> 位置、速度、加速度状态估计
  -> 齿轮比、起点与偏置映射
  -> 位置误差修正 + 主机速度前馈
  -> 从机速度 PI + 加速度/摩擦电流前馈
  -> 总 Iq 限幅及外环抗积分饱和
  -> 原有 dq 电流环、FOC 与保护
```

一个便于在现有串级结构中落地的表达式为：

```text
theta_ref = theta_slave_0 + offset + k*(theta_master-theta_master_0)
omega_ref = k*omega_master_estimated
alpha_ref = k*alpha_master_estimated

omega_command = omega_ref + Kp_position*(theta_ref-theta_slave)
Iq_feedback = PI_velocity(omega_command-omega_slave)
Iq_feedforward = Ka_current*alpha_ref + Kv_current*omega_ref + Iq_friction
Iq_command = saturate(Iq_feedback + Iq_feedforward)

理想刚性轴模型：Ka_current = J_equivalent/Kt，Kv_current = B/Kt
```

这里重点增加的是加速/制动所需电流的前馈，并减少参考与测速的额外滞后。R31 已尝试直接位置和速度前馈，不能仅恢复 R31 就声称实现了这套方案。

参数与实现条件：

1. 先采集实测 Iq 给定/反馈、主从角度/速度、母线电压、控制耗时，确认电流环、速度环以及电压/电流饱和情况。应先整定内环，再整定位置误差修正。
2. 用有界试验辨识电流到角加速度增益及摩擦。供应商的 0.23 Nm/A 未说明相/线、峰值/RMS 口径，不能直接当本工程 dq Iq 对应的 Kt。也可直接辨识 Ka_current，不必分别辨识 J 和 Kt。
3. 采用固定增益 alpha-beta-gamma 或同类状态观测器，估计主机速度/加速度；两轴反馈测速也需评估相位与噪声。应按样本时间戳处理新数据、丢帧和恢复，不能将原始 14 位角度直接二次差分作为电流前馈。观测器仍有噪声/滞后折中，无法预知任意突然反向。
4. 电流前馈与反馈求和后统一限幅，保留反馈修正余量；外环积分根据实际可用输出做条件积分或回算。切换 Follow/Stop、换方向、掉线恢复时初始化观察器和积分，避免前馈突跳。
5. 总电流、母线、速度、编码器有效性和定时保护继续有效。对不可实现的主机动作采取明确的能力约束；将重复速度斜坡整合成一处经验证的约束，不能简单取消全部限制。
6. 加速度估计和模型误差可能增加超调，应从较小权重验证。零速摩擦补偿需连续过渡，避免 sign(speed) 在往复过零时产生电流跳变。

## 其他算法的选择

| 方法 | 对本场景的建议 |
| --- | --- |
| 直接跟随＋速度/加速度前馈＋反馈修正 | 第一阶段首选；沿用现有有感 FOC，变化和参数含义清楚 |
| 位置 PD 直接输出转矩/Iq＋惯量前馈 | 可作为后续两自由度位置伺服方案；D 使用速度误差，需先辨识模型和验证电流环，再与串级结构比较，避免同时堆叠控制器 |
| DOB/ESO/ADRC 扰动补偿 | 适合负载、摩擦变化造成的误差，可第二阶段加入；观测带宽受测量噪声、离散实现与模型约束，不能自动补足执行器能力 |
| 更强的追赶/S 曲线平滑 | 适合大位移、平稳到位；持续移动的手动目标需要低相位滞后，不宜仅靠继续增加平滑环节解决 |
| 增大位置积分 | 不作为高速往复的首选；先解决参考、相位、前馈和饱和问题，静态残差再考虑小积分 |

## 如何判断改善

用户确认的主要验收工况为 **4015 空载、1:1 跟随、±10°、4 Hz**，具体角度误差与相位容差尚未约定。以同一电机、母线、负载和限流，比较 ±5°/±10° 的 0.5、1、2、3、4 Hz 目标，频率逐步增加；5 Hz 可作为额外能力检查。记录原始主从角度、参考角度、速度估计、Iq 给定/反馈和限幅标志；分别计算幅值比、相位差、RMS/峰值角误差及峰值电流。不要仅看阶跃到达时间或目测流畅程度。

4 Hz 时，每 5 ms 纯延迟对应 7.2° 周期相位，每 20 ms 对应 28.8°；这不是电机机械角误差，也不能把滤波时间常数简单等效为同值纯延迟。该换算用于说明后续应将参考生成、测速、通信与环路相位一起评估。

算法验证须包含突停、反向、较大角度、饱和、两轴互换、编码器丢帧、Stop/Follow 重启。原有模型需补充电压约束与辨识后的惯量；没有实测辨识前不承诺可跟随频率。初期可沿用 1 kHz 外环/10 kHz 电流环，不必先改 CubeMX；是否调整采样和环路频率应由时延与 CPU 预算实测决定。当前 Flash 余量较小，落地时需重新核对构建资源。

## 一手资料与适用范围

- [Kollmorgen Feed Forward](https://www.kollmorgen.com/en-us/developer-network/Feed-Forward)：区分位置环输出端的速度前馈与速度环输出端的电流/惯量前馈；给出零速附近连续摩擦补偿。使用其控制结构，不照抄驱动器归一化参数。
- [Kollmorgen AKD2G Torque Feed Forward](https://webhelp.kollmorgen.com/akd2g/english/content/Tuning/Torque-FeedForwards.htm)：加速度前馈补偿惯量，速度相关电流前馈补偿黏性摩擦，使电流需求不完全依赖跟随误差。
- [Beckhoff Feedforward Control — Description](https://infosys.beckhoff.com/content/1033/tf5200_feedforward_control/308333707.html)：说明速度、加速度、jerk 前馈与位置滞后的关系；也明确提醒权重不当可能超调。
- [MathWorks trackingABF](https://www.mathworks.com/help/fusion/ref/trackingabf.html)：alpha-beta-gamma 状态估计的位置/速度/加速度结构参考；并非直接移植 MATLAB 运行时或保证其适用于本板参数。
- [MathWorks Anti-Windup Control](https://www.mathworks.com/help/simulink/slref/anti-windup-control-using-a-pid-controller.html)：介绍饱和回算/条件积分，特别说明存在前馈时需让积分跟踪反馈控制器实际承担的输出。
- [Sariyildiz 等：离散时间 DOB 稳定性与鲁棒性论文](https://arxiv.org/abs/2010.08075)：说明 DOB 的模型、带宽、测量噪声和离散稳定性约束，支持将其作为后续受控改进而非无限增益补偿。

以上优先级和针对本板的结构建议属于结合资料与当前代码的工程判断，尚不是完成辨识后的控制器设计。
