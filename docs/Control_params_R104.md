# R104：公共控制路径整理与测量参数应用

固件为 `UI-R104-PAR`。本轮完成公共初始化／复位、测速窗口和冷路径文本整理，并把辨识结果接入两轴控制参数。保留现有运行模式、驱动、保护和通信；CubeMX 无需调整。

## 操作方式

1. 使用正确的电机型号，在 Single M1 编码器模式完成辨识。结果页前四屏仍通过 OK 保存测量结果。
2. 松开按键，等待保存完成。保存结果本身不会改变正在使用的控制参数。
3. 在辨识页用左／右切到 `Apply M1` 或 `Apply M2`，按 OK 显式应用。必须两轴停止、没有对齐／辨识／联动运行，目标轴使用编码器且编码器通信健康；测量型号必须与目标轴当前型号一致。
4. 应用会清零该轴运动目标并使旧对齐失效，随后按原规则重新对齐。确认保存完成后再断电；运动仍由操作员发起。
5. `Preset M1`／`Preset M2` 恢复该轴的厂家预设电参，同样要求停机并重新对齐。恢复全部默认设置也会清除应用记录。

测量覆盖极对数、等效星形 Rs／Ls 和磁链；M1 同时使用辨识出的编码器方向。向 M2 复制电参时保留 M2 原有预设编码器方向，不能把 M1 编码器的安装方向直接当作 M2 的方向。两轴的相序和编码器安装方向仍需各自正确。

保护电流、过载预算、型号速度／电压上限，以及原位置／速度／跟随参数继续来自型号预设。辨识结果不会自动提高电流或解除保护。

## 上位机与查询

单文件 HTML 的“电机参数辨识”区域增加应用到 M1／M2、应用保存的测量值、恢复预设、读取已应用参数。连接仍先切 Native 再 Get；新增应用操作要求固件 R104。取消确认不发送命令，收到拒绝后不重试运动。

| 操作 | 命令 |
| --- | --- |
| 保存本次辨识结果 | `App:0,15,0` |
| 将已保存结果应用到轴 a | `App:a,18,0` |
| 恢复轴 a 的预设电参 | `App:a,19,0` |
| 查询轴 a 当前电参 | `GetRow:a,0,15` |

`a` 为 1 或 2。Drive 诊断追加查询行 `R/L/Flux`，原有行号保持。返回如 `M:1920/440/9290`，M 为已应用测量值、P 为型号预设；原始单位依次为 mΩ、µH、µWb。HTML 转为 Ω、µH、mWb 显示。Native 配置包仍为 schema 2、92 B 载荷，JustFloat 通道布局不变。设置 JSON 的可编辑配置导入仍不包含辨识结果，不会隐式应用电参。

## 存储与型号绑定

W25Q64 设置版本由 v5 升至 v6，记录为 124 B，仍使用原来的 A/B 日志区和 CRC。保留旧版设置及测量结果；v1～v5 结果缺少可信型号标记，只供查看，需重新辨识、保存后才允许应用，不会在升级时自动接管控制。

每轴保存一份最近应用的记录，带电机型号标记。当前型号匹配时使用测量值，切到另一型号时使用其预设，切回来恢复该记录。向同一轴应用另一型号的新结果会覆盖旧应用记录；本轮没有扩成四套独立校准槽。测量结果区与两个轴的应用记录分别保存，后续辨识／保存不会自行改变已应用值。

`motor_detect` 的低 24 位继续保留原极对数／Rs 格式，高字节为型号 + 1。应用前检查完整参数范围、轴、型号和停机条件；拒绝请求不发布半套控制参数。

## 控制与体积整理

- M1／M2 共用控制器初始化和复位函数，减少重复结构和分支。
- 电流 PI 统一由参数生成：`Kp = Ls × 250`、`Ki = Rs × 250`。250 rad/s 是沿用预设的设计带宽，不是实测带宽。例如 1.92 Ω、440 µH 对应 Kp = 0.11、Ki = 480。磁链随参数装载进入现有 HSO 接口。
- 合并两轴原有的四点差分测速窗口，逐样本核对旧算式；本轮尚未引入时间戳测速／PLL，也未改变跟随算法。
- 共享冷路径状态字符串，压缩指针表；合并常用限幅和 UI 输出路径。原有文字内容、字形及保护判定保留。
- 将 1 kHz 通用 PID／低通函数放回 Flash，快速 FOC／调制函数继续保留原 RAM 放置。需要实板重新测量 Ctrl Max／HSO Time；主机回归不能证明实际执行时间。

ST HAL／LL／CMSIS、USB 中间件、HSO 官方库、KK_UI／KK_OLED 核心、生成初始化、`.ioc` 和编译选项保持本轮基线。每次构建继续执行 CubeMX 配置检查，SPI／DMA 和 KEY1 映射规则保持。
