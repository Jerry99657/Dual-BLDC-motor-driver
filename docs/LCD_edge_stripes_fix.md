# LCD 上边与右边彩条修复（UI-R23-LCD）

## 已定位的可见区寻址错误

用户提供的 `D:/Data/Downloads/0.96寸初始化BOE+ST7735S.c` 中，`address()` 明确写入：

```text
MADCTL = 0x08
CASET  = 0x0018 .. 0x0067  → 列 24 .. 103，共 80 列
RASET  = 0x0000 .. 0x009F  → 行  0 .. 159，共 160 行
```

原驱动使用列偏移 26、行偏移 1，实际刷新范围变成列 26..105、行 1..160，与本块 BOE 模组的可见区域不匹配。可见区内列 24、25 和行 0 没有被写入。`Core/Src/main.c` 使用 270° 软件旋转，因而对应照片中的上边两行、右边一列漏刷，同时另两侧内容发生裁切。

已将具体驱动的偏移修正为 **列 24、行 0**。普通刷新、DMA 和阻塞刷新共用同一寻址函数，仍保留 MADCTL=0x08，由图形核心完成软件旋转。模组分辨率、原有黑白配色和初始化电源/Gamma 参数保留。另一份 `lcd.c` 含多套显示初始化及注释分支；本次可见区地址以明确标注 BOE+ST7735S 的专用文件为依据。

## 同时修复的初始化与时钟问题

ST7735S 的 GRAM 为 132×162，RAMWR 章节说明上电内容随机，软复位和硬复位均不清除显存。原驱动只初始化带偏移的 80×160 区域，窗口之外仍可能保留彩色随机像素；这与上述漏刷叠加后会形成固定边缘彩条。

现在在 DISPON 前清完整 GRAM，使用原有 1280 字节分块缓冲，共发送 42768 字节，最后一块按剩余长度发送，不增加 MCU 全屏 RGB565 缓冲。屏幕错误恢复时重新初始化，也执行同样清屏。原生坐标窗口与裸 GRAM 坐标窗口分开，并检查范围及包含式结束坐标，避免偏移被重复应用。

另外，SPI3 原先 170 MHz / 8 = 21.25 MHz（周期约 47.1 ns），超出 ST7735S 四线写接口最小 66 ns 周期要求。已同步修改 `FOC_two.ioc` 和 `Core/Src/spi.c`，改为 /16，即 **10.625 MHz**（约 94.1 ns）。这会增加单帧传输时间；DMA 分块及原有异步完成/恢复逻辑继续保留。

资料：[ST7735S 数据手册，4-line serial timing 与 RAMWR defaults](https://files.waveshare.com/upload/e/e2/ST7735S_V1.1_20111121.pdf)。模组地址依据用户本地 BOE 示例，而非其他厂商模组的通用偏移。

## 回归证据

`tests/oled_driver_host/test_driver.c` 增加完整 ST7735S 命令/数据、包含式窗口与 GRAM 模型，初始填入彩色数据，按厂家地址独立建立可见区检查：

1. 原代码在初始化后仍有未清除的 GRAM，回归测试失败。
2. 单独补全清屏但仍用 26/1 偏移时，BOE 可见区的像素比对仍失败，证明清屏不足以修正图像映射。
3. 改为 24/0 后，初始化全显存清屏、四种软件旋转下的四边框、局部刷新、精确 RGB565 字节数、DMA 提前完成/失败/中止及重新初始化测试通过。

`python tests/ui_host/run.py` 同时通过现有 UI、按键、动画、存储和真实显示驱动回归。主机模型证明发送地址及数据符合厂家示例，不代替实物显示验收。
